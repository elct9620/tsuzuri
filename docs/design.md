# Tsuzuri 設計

Tsuzuri（綴り）在本機把影片與音訊轉成字幕，並提供翻譯與校對，音訊與文字不離開使用者的電腦。它為有隱私需求、不能上傳雲端的情境而生。這份文件記錄設計的意圖與取捨，行為與介面的細節以 `.spec/` 為準。

## 0 總覽

### 0.1 設計承諾

| 承諾 | 意義 |
|---|---|
| 本機處理 | 音訊與文字不離開電腦；網路只用於首次設定、更新與使用者主動下載 |
| 元件內建且可覆寫 | 安裝檔內建能在各平台執行的元件；使用者指定的版本永遠優先 |
| 一次只載入一個模型 | 各 Step 依序執行，前一個模型釋放才載入下一個，4GB VRAM 也能用 |
| 不留下行程 | 不論正常結束或當掉，都不讓元件行程繼續佔用記憶體或 port |
| 流程由使用者組合 | 轉錄、說話者辨識與翻譯是模組，三種模式只是預設的組合 |

這五項是設計的固定點。兩項衝突時，由該章說明哪一項讓步。

### 0.2 系統分層

| 意圖 | 做法 |
|---|---|
| 單一事實來源 | Webview 顯示的資料都向 Rust 查詢，變更也都寫進 Rust |
| 介面不被拖慢 | 資料處理留在 Rust，Webview 只負責畫面、互動與多語系 |
| 當掉不影響介面 | 運算都在元件的子行程，GPU 或記憶體出問題只結束該行程 |

分層、模組與相依規則見 `docs/architecture.md`。

## 1 字幕資料

所有模組都讀寫同一種資料，沒有相依。

### 1.1 Segment 與 Transcript

| 概念 | 內容 |
|---|---|
| Segment | 一段語音：開始時間、結束時間、說話者（可省略）、文字；翻譯後另有譯文 |
| Transcript | 一個媒體檔的所有 Segment，依時間排序 |
| 譯文 | 一次只帶一種語言；每段譯文靠開始與結束時間對上原文 Segment |
| 多語言對照 | 尚不需要；需要時譯文改成依語言分開保存，編輯指令帶上語言，顯示可選多種譯文 |

模組之間只交換 Transcript，不交換各元件自己的輸出格式。這讓轉錄可以換引擎、翻譯可以接既有字幕，而不影響其他模組。

### 1.2 SRT 讀寫

| 情況 | 處理 |
|---|---|
| BOM | 讀入時清除，寫出一律不帶；部分播放器遇到 BOM 會顯示亂碼 |
| CRLF | 讀入時與 LF 相同 |
| 說話者 | 第一行開頭的 `標籤:`，例如 `co:`、`cl:`，在其他行沒有標籤時成為 Segment 的說話者；寫出時以 `標籤: ` 加回原文開頭；譯文開頭用詞彙表在該語言的說話者名稱（9.3），沒有時相同。讀入譯文不推測標籤，只拿掉原文說話者的那一個。多行各有標籤時保留在文字裡 |
| 一段文字有多行 | 保留換行 |
| 時間格式錯誤 | 失敗，並指出是第幾段 |
| 編輯後的文字含空行 | 寫出時移除空行，避免一段被切成兩段 |

SRT 是 Transcript 交換的唯一格式：whisper-cli 輸出它、使用者提供它、匯出也用它。

### 1.3 雙語 SRT

```
  1
  00:00:01,000 --> 00:00:03,500
  CO: 今天我們來談隱私               ← 原文（預設在上）
  CO: Today we talk about privacy    ← 譯文
```

| 情況 | 處理 |
|---|---|
| 順序 | 預設原文在上；專案設定可改成譯文在上，檔名的語言代碼也依此順序 |
| 說話者 | 原文與譯文的開頭各加上自己的說話者名稱；沒有另外指定時兩行相同 |
| 某段沒有譯文 | 只寫出原文 |
| 讀入雙語 SRT | 由使用者選擇是否拆成原文與譯文；預設整段當成原文 |

一份字幕同時顯示兩種語言，播放器不需要額外支援。有些軟體的字幕本來就會換行，無法自動判斷是否為雙語，所以讀入時由使用者決定。

## 2 專案

專案對應一個目錄，收納同一系列作品的媒體檔、字幕與設定，例如一部作品的各集。相依：第 1 章。

### 2.1 專案目錄

```
  lecture/                     ← 專案
  ├── tsuzuri.config.json      ← 專案設定（2.3）
  ├── glossary.csv             ← 翻譯詞彙表（9.3）
  ├── .tsuzuri/history/        ← 產出與覆蓋前的備份（2.4），不當成資源
  ├── ep01.mp4  ┐
  ├── ep01.srt  ├ 資源 ep01：媒體檔、主語言字幕、en 譯文
  ├── ep01.en.srt ┘
  ├── ep02.mp4                 ← 資源 ep02：只有媒體檔，可以轉錄
  └── ep03.srt                 ← 資源 ep03：只有字幕，可以編輯與翻譯
```

| 概念 | 內容 |
|---|---|
| 資源 | 同一個檔名的媒體檔與字幕，一集或一段錄音 |
| 目前資源 | 編輯畫面與任務的對象，一次一個 |

目錄就是事實來源，Tsuzuri 不另外儲存字幕的副本。只有字幕的資源就是單純編輯字幕。

### 2.2 資源配對

| 檔案 | 角色 |
|---|---|
| `[name]` 加上內建 ffmpeg 能讀的副檔名 | 媒體檔：`.mp4`、`.mov`、`.m4a`、`.mkv`、`.webm`、`.mp3`、`.wav`、`.ogg`、`.opus`、`.flac`、`.aac` |
| `[name].srt` | 主語言字幕 |
| `[name].[主語言].srt` | 主語言字幕；與 `[name].srt` 並存時用 `[name].srt` |
| `[name].[lang].srt` | `lang` 譯文，`lang` 是主語言以外的語言 |
| `[name].[lang].[lang].srt` | 雙語匯出，不載入 |
| 不認得的語言代碼 | 不載入 |

譯文依開始與結束時間對上主語言的段落，對不上的段落沒有譯文。同一資源可以有多種譯文，一次編輯一種。

### 2.3 專案設定

| 設定 | 沒有設定檔時 |
|---|---|
| 主語言 | 介面語言對應的語言：正體中文為 `zh-TW`，其他為 `en` |
| 翻譯語言 | 未指定；翻譯後記下 |
| 雙語順序 | 原文在上（1.3） |
| 自動儲存雙語 | 關閉 |
| 覆蓋前備份 | 關閉 |

```
  軟體設定（預設值） ─▶ 專案設定（覆寫） ─▶ 任務的選項（只用這一次）
```

專案設定存在 `tsuzuri.config.json`，第一次改動時建立。主語言在設定畫面修改，轉錄與翻譯都以它為原文語言。

### 2.4 寫回與開啟

| 時機 | 做法 |
|---|---|
| 編輯原文 | 立即寫回主語言字幕 |
| 編輯譯文 | 立即寫回目前的 `[name].[lang].srt` |
| 編輯說話者 | 寫回原文，並把說話者帶到每種譯文裡時間相同的段落；時間對不上的不動 |
| 轉錄完成 | 寫出 `[name].srt`；已存在時先詢問是否覆蓋。說話者依時間帶到每種譯文，有改變的譯文才寫入 |
| 翻譯完成 | 寫出 `[name].[lang].srt` |
| 轉錄或翻譯寫出後 | 一律把寫出的字幕複製成產出備份 `.tsuzuri/history/[name][.lang].[UTC 時間].output.srt`，作為之後編輯的比較對象 |
| 開啟目錄 | 掃描資源，選取第一個 |
| 開啟 SRT | 開啟它所在的目錄，選取該資源 |
| 還原備份 | 先把目前的字幕留成覆蓋前備份，再以選的備份取代，重新讀取目前資源 |
| 覆蓋前備份開啟時 | 轉錄或翻譯要覆蓋已有的字幕前，先複製到 `.tsuzuri/history/[name][.lang].[UTC 時間].srt` |
| 每次改動字幕前 | 編輯、段落變更、還原與任務寫出前，記下這個資源所有字幕的內容，最多 100 步，專案開著時可以復原與重做；外部改過就清掉，復原不另留備份 |
| 任務進行中 | 轉錄時整個資源不能改，翻譯時只有寫入的那份譯文不能改；結束後恢復 |
| 自動儲存雙語開啟時 | 寫出原文後，更新這個資源每種譯文的 `[name].[a].[b].srt`；寫出譯文後只更新那一種；順序依雙語順序 |
| 切回視窗 | 目前資源的字幕在外部改過時重新讀取 |
| 寫回前 | 檔案內容與上次讀寫時不同，就重新讀取、這次的修改不寫入，並告知使用者 |

自動寫回讓關掉 App 不會遺失結果，字幕也直接能交給播放器。字幕常在專業字幕軟體裡再修，所以寫回前先比對內容，外部的修正不會被自動寫回蓋掉。不比對修改時間，因為有些檔案系統的時間不夠精細，緊接的兩次寫入會一樣。

### 2.5 最近的專案

| 欄位 | 內容 |
|---|---|
| 名稱 | 目錄名稱 |
| 路徑 | 目錄完整路徑 |

## 3 行程

元件以子行程執行，沒有相依。

### 3.1 啟動與紀錄

```
  Processes::spawn(絕對路徑)
    ├ 記錄 PID 與執行檔名稱到 app data
    ├ 轉送 stdout、stderr 給呼叫端，並逐行寫入 log
    └ 行程結束 → 從紀錄移除
```

一律以絕對路徑啟動，不用 Tauri 的 sidecar，因為元件不一定來自安裝檔。元件由 App 直接啟動，不再開子行程，所以紀錄涵蓋全部行程。log 同時印到終端機與寫入檔案，預設在系統的 log 目錄，macOS 上是 `~/Library/Logs/me.aotoki.tsuzuri/`；設定頁可以改用別的目錄，重新啟動後生效。

### 3.2 清理

| 情境 | 機制 |
|---|---|
| App 正常結束 | 在 `RunEvent::Exit` kill 仍在執行的子行程 |
| App 當掉或被強制結束 | 下次啟動時，kill 紀錄中還活著且名稱相符的行程（Windows 用 `taskkill /T /F`） |
| PID 已被其他程式重用 | 名稱不符就不動它 |

`tauri-plugin-shell` 只清理從 JS 端啟動的行程，所以 App 自己負責 Rust 端啟動的行程。當掉後的殘留會佔著 VRAM 直到下次啟動。

## 4 元件

相依：第 3 章，元件以行程執行。

### 4.1 尋找順序

```
  使用者指定的執行檔（例如 CUDA 版）
        │ 沒有，或檔案不在
        ▼
  偵測已安裝的版本（PATH、Homebrew、Nix；要能回應版本參數）
        │ 找不到
        ▼
  安裝檔內建的變體（依 0.4 自動選擇）
        │ 沒有
        ▼
  提示怎麼安裝
```

使用者指定的永遠優先，這是 CUDA 等進階設定的入口。macOS 的 App 讀不到 shell 的 PATH，所以常見的安裝目錄逐一列出。

### 4.2 內建變體

| 元件 | 變體 | 理由 |
|---|---|---|
| whisper.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 上游會刪除舊的 nightly，不能釘上游的執行檔 |
| llama.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 與 whisper.cpp 一致 |
| ffmpeg | 純音訊的 LGPL 版 | 只需要解出音軌，範圍小、授權單純 |

App 不在執行時下載元件。內建變體放在 `components/<元件>/<變體>/`，App 照 Build Manifest 列出的順序逐一嘗試，採用第一個能執行的變體；選擇結果顯示在設定頁，可以手動改。目前安裝檔只內建第一個變體，其他變體與 CUDA 版由使用者依 12.2 指定。

### 4.3 自行編譯

| 平台 | 編譯環境 |
|---|---|
| Windows | GitHub Actions 的 Windows runner，在 MSYS2 UCRT64 編譯，附上執行需要的 DLL |
| Linux | GitHub Actions 的 Linux runner，使用系統的 OpenBLAS、Vulkan 函式庫 |
| macOS | GitHub Actions 的 macOS runner，靜態連結 |

原始程式碼的版本、SHA256 與各平台的變體記在 `components.json`（Build Manifest），CI 與開發機跑同一支 `scripts/vendor.sh`。ffmpeg 的 `configure` 在 Windows 需要 MSYS2，所以 Windows 全部在那裡編譯。`vendor/` 與安裝檔同樣是 `<元件>/<變體>/` 的結構，開發時的 debug build 會先偵測它；打包時合併 `tauri.bundle.conf.json`，把 `vendor/` 放進安裝檔的 resources。

### 4.4 授權

| 元件 | 授權 | 我們的義務 |
|---|---|---|
| whisper.cpp、llama.cpp | MIT | 附上授權聲明 |
| ffmpeg | LGPL 2.1+ | 不開 GPL、nonfree；隨版本附上對應的原始程式碼；標示 FFmpeg 授權 |
| Rust 相依套件 | 見 `deny.toml` | cargo-deny 檢查、cargo-about 產生授權聲明 |
| Webview 打包套件 | 與 Rust 相同的允許清單（`about.toml`） | `scripts/webview-licenses.ts` 檢查並產生 `THIRD-PARTY-LICENSES-WEBVIEW.html`，含只在建置時用到、CSS 卻打包進去的 daisyUI 與 Tailwind |

ffmpeg 是獨立執行檔，Tsuzuri 不連結它的函式庫，使用者也能改用自己的 ffmpeg。純音訊版不含視訊解碼器。

## 5 模型

模型由使用者提供，沒有相依。

### 5.1 指定與檢查

| 用途 | 已驗證的模型 | 規則 |
|---|---|---|
| 轉錄 | Breeze-ASR-25（中文） | 指定本機檔案並記住；啟動引擎前檢查檔案還在 |

## 6 工作流程

相依：第 1、3～5 章，流程串起的模組需要字幕資料、行程、元件與模型。

### 6.1 模組與流程

```
  媒體檔 ─▶ [轉錄模組] ─┐
                        ▼
  SRT 檔 ───────────▶ Transcript ─▶ [說話者辨識模組] ─▶ [翻譯模組]
                                     可選，需要媒體檔        │
                                                             ▼
                                                  Transcript（含譯文）
```

模組以 Transcript 為輸入或輸出，使用者可以組合它們。流程依序執行，前一個模組的行程全部結束後，下一個才開始。

### 6.2 任務

```
  字幕編輯（目前資源）
    ├─ [轉錄] ─▶ 轉錄模組 ─┬─▶ 段落逐段出現在編輯畫面
    │                        └─ 勾選完成後翻譯 ─┐
    └─ [翻譯] ─────────────────────────────────┴─▶ 翻譯模組 ─▶ 譯文逐批出現
```

| 任務 | 組成 | 可以開始的資源 |
|---|---|---|
| 轉錄 | 轉錄模組 | 有媒體檔 |
| 翻譯 | 翻譯模組 | 有主語言字幕 |
| 轉錄後翻譯 | 轉錄模組 → 翻譯模組 | 有媒體檔 |

Tsuzuri 以字幕翻譯為主，編輯畫面是基本狀態，任務從它的 modal 開始，一次只跑一個。任務寫入的字幕在進行中不能改，結果算一步復原（2.4）。轉錄是翻譯的前置動作，勾選完成後翻譯時，轉錄的 modal 也列出翻譯的選項。目前組合寫死在程式裡，改成可組合後變成內建範本。

### 6.3 進度與取消

| 規則 | 說明 |
|---|---|
| 每個模組回報進度 | 名稱、百分比，能算就附「第 N / 共 M」 |
| Phase 序列 | 畫面依任務列出會經過的 Phase，標出走過與目前的 |
| 算不出進度時 | 顯示不定進度，例如載入模型 |
| 顯示位置 | 任務進行中顯示在編輯畫面上方，結果也在同一畫面逐步出現；結束後進度消失，完成或失敗改以通知告知 |
| 取消 | 結束目前的行程，已完成的 Transcript 保留 |

載入模型以不定進度顯示；Metal shader 在第一次載入時才編譯，冷啟動約 30 秒；偵測 llama-server 也會觸發，約 17 秒。轉檔仍沒有百分比。

### 6.4 模型的狀態

```
            翻譯開始                          翻譯結束
  [空閒] ──────────▶ [載入翻譯模型] ──▶ [翻譯中] ──────▶ [保留 N 秒]
    ▲  ▲                                                   │    │
    │  └──────────────── 時間到，釋放 ──────────────────────┘    │
    │          轉錄結束                               轉錄開始，先釋放
    └──────────────────── [轉錄中] ◀───────────────────────────┘
  [空閒] ── 轉錄開始 ──────▶ [轉錄中]
```

| 規則 | 做法 |
|---|---|
| 一次一個任務 | 轉錄、翻譯與關掉常駐都先取得同一把鎖，後來的排隊，不打斷進行中的任務 |
| 轉錄開始 | 先釋放翻譯模型；釋放不了就停止 llama-server |
| 保留期間再翻譯 | 取消排定的釋放，沿用已載入的模型 |

目前以一把鎖守住這些轉移，沒有明確的狀態列舉。流程改成可組合時，再把狀態與轉移寫成狀態機。

## 7 轉錄模組

相依：第 6 章，以模組身分加入流程。

### 7.1 Step

```
  媒體檔 ─▶ ffmpeg ─▶ 16kHz 單聲道 WAV ─▶ whisper-cli ─▶ SRT ─▶ Transcript
```

先轉成統一格式，轉檔失敗與轉錄失敗可以分開診斷。兩個 Step 依序執行，whisper-cli 結束即釋放記憶體。

### 7.2 語言

| 設定 | 設計 |
|---|---|
| 轉錄語言 | 專案的主語言（2.3）；傳給 whisper-cli 的 `-l` |
| 語言清單 | 繁體中文、英文、日文，與翻譯共用 |
| 模型建議 | 依語言建議模型；Breeze-ASR-25 只適合中文 |

轉錄結果寫成主語言字幕，所以語言跟著專案，不在任務裡另選。每個代碼對各元件的意義只記在 Rust。模型建議尚未決定。

### 7.3 進度與串流

| 來源 | 內容 |
|---|---|
| stderr `main: processing` | 模型載入完成，開始轉錄 |
| stderr `progress = N%`（`-pp`） | 轉錄的百分比 |
| stdout `[開始 --> 結束]  文字` | 剛轉錄完成的段落 |
| 輸出 SRT | 結束時定稿，取代逐段累積的段落 |

whisper-cli 每處理完約 30 秒的音訊，就送出一批段落與百分比；經過 pipe 也不會延到結束才送。段落逐批加進目前資源，編輯畫面跟著長出來。轉檔尚無百分比。完成時回報音檔長度與轉錄耗時，用來計算 RTF。

## 8 說話者辨識模組

相依：第 6、7 章，以模組身分加入流程，需要轉錄產出的 Transcript。

### 8.1 Step

```
  媒體檔、Transcript ─▶ [說話者辨識] ─▶ 標上說話者的 Transcript
```

| 規則 | 說明 |
|---|---|
| 輸入 | 媒體檔與轉錄產出 Transcript |
| 輸出 | 每個 Segment 標上說話者 |
| 開啟方式 | 專案設定或執行時的選項，預設關閉 |

whisper.cpp 不支援說話者辨識，所以在轉錄之後另外辨識。辨識與對應說話者的做法尚未決定。

### 8.2 工具選擇

| 條件 | 理由 |
|---|---|
| 在本機執行 | 設計承諾「本機處理」 |
| 結束即釋放記憶體 | 設計承諾「一次只載入一個模型」 |
| 授權允許隨 App 散布 | 同第 4.4 章的元件 |

候選工具尚待評估，這三項是選擇時的最低條件。

## 9 翻譯模組

相依：第 6 章，以模組身分加入流程。機制參考翻譯 PoC（qwen-translator-script），它針對小模型常見的漏翻、重複、跨句錯位設計了分層的修復。

### 9.1 llama-server 生命週期

```
  App 啟動 ─▶ 背景啟動 router，不載入模型
  翻譯開始 ─▶ /models/load ─▶ 等到載入完成 ─▶ 送出各批翻譯
  翻譯結束 ─▶ 保留 N 秒 ─▶ /models/unload
  App 結束 ─▶ 停止 router 與它的模型行程
```

| 請求 | 做法 |
|---|---|
| 介面 | OpenAI 相容的 chat completions，以 async-openai 送出 |
| 內容 | 一批句子，各帶 index；前一批最後幾句的原文與譯文當參考 |
| 回應 | 以 JSON schema 限定格式，依 index 對回各句 |
| 思考模式 | 以 `chat-template-kwargs` 關閉，翻字幕用不到 |

| 常駐 | 做法 |
|---|---|
| 模型與參數 | Tsuzuri 寫一份 preset：模型路徑、context 4096、關閉思考；換模型時重讀 |
| 一次一個 | `--models-max 1`、`--no-models-autoload`，只在翻譯開始時載入 |
| 保留 N 秒 | 由 Tsuzuri 計時後釋放，預設 0；改秒數不必重啟 router |
| 轉錄開始 | 先釋放翻譯模型，維持一次只載入一個模型 |
| 關掉常駐 | 每次翻譯啟動單一模型的 llama-server，結束就停止 |
| router 意外結束 | 下一次翻譯重新啟動 |

常駐省下每次翻譯啟動與關閉行程，router 不載入模型時不佔模型的記憶體。context 固定 4096，避免撐爆 VRAM。

### 9.2 分批

| 規則 | 說明 |
|---|---|
| 每批數句 | PoC 預設 8 句，比逐句翻譯少很多請求 |
| 同一句不拆開 | 被切成多段的一句話排在同一批 |
| 失敗就拆半 | 重試多次仍失敗時，把該批拆成兩半再試 |
| 說話者標籤 | 使用者開啟時，只送對話本體，譯完原樣接回；冒號前是純數字的時間不算標籤，譯完行數變了就不接回 |

```
  以重疊兩句的視窗請模型找出被切開的句子 ─▶ 同一句排進同一批 ─▶ 依序翻譯各批
```

偵測在翻譯之前的 detect Phase 依序進行，失敗的視窗略過。串成超過兩倍批次大小的一組就不再保持完整，退回固定分批，避免請求撐爆 context。

### 9.3 翻譯詞彙表

| 設定 | 設計 |
|---|---|
| 格式 | CSV，每一欄是一種語言，標頭為語言代碼，例如 `zh-TW,en,ja`；每一列是同一個詞的各語言寫法 |
| `type` 欄 | 最後一欄，`speaker` 表示這個詞是說話者名稱；沒有這一欄的檔案照常讀，視為沒有說話者 |
| 翻譯時 | 主語言欄是原文、目標語言欄是譯文；其中一欄空白的列不用 |
| `source,target` 標頭 | 專案已記下翻譯語言時，視為主語言與翻譯語言；否則視為標頭錯誤 |
| 來源 | 專案目錄裡的 `glossary.csv`；開啟專案與每次翻譯前讀取，沒有就不使用 |
| 編輯 | 詞彙表 modal 以表格列出所有支援的語言與說話者勾選；沒有檔案時由此建立，儲存時標頭寫成語言代碼與 `type` |
| 帶入方式 | 每批只帶入有出現在該批原文裡的詞 |
| 檢查 | 譯文沒照詞彙表時重試，仍不符就保留目前最好的版本 |

小模型對陌生的專有名詞容易猜錯。以語言分欄，同一份詞彙表就能譯成任何一種語言。同一系列作品共用一份，改完下次翻譯即套用。說話者名稱也是詞，台詞裡叫到名字時譯法和標籤一致。它跟 `.spec/glossary.md` 無關。

### 9.4 滾動摘要

| 設定 | 設計 |
|---|---|
| 內容 | 不超過指定字數的前文摘要，每翻完一批更新一次；更新失敗就沿用上一版 |
| 代價 | 每批多一次請求；PoC 實測總時間約多 30% |
| 限制 | 沒搭配翻譯詞彙表時，模型會把摘要裡的人名錯套到其他人 |

補足分批只看得到附近幾句的限制。因為有錯套人名的風險，只在有翻譯詞彙表時建議開啟。

### 9.5 自我修復

| 偵測到 | 處理 |
|---|---|
| 重複、漏翻、殘留原文、預留字 | 重試；仍失敗就保留原文 |
| 違反翻譯詞彙表、疑似吃掉否定詞 | 重試；仍失敗就保留目前最好的版本 |
| 自我檢查認為譯文屬於鄰句 | 重試；仍失敗就保留目前最好的版本 |
| 回應不是合法 JSON | 附上更正說明重試 |
| llama-server 無法回應 | 停止翻譯，不把原文當成譯文 |

```
  整批送出 ─▶ 有問題的句子帶前後文重試 ─▶ 仍失敗就拆半 ─▶ 剩一句仍失敗就退回
```

確定翻壞就不留下；問題輕微時，寧可保留不完美的譯文。殘留原文只在翻成英文時檢查；否定詞檢查只支援中翻英。

### 9.6 自我檢查

| 設定 | 設計 |
|---|---|
| 做法 | 每兩句一次請求，模型先重述譯文的意思，再指出它對應哪一句 |
| 範圍 | 只抓「內容跑到鄰句」，不判斷是否完整；檢查的回應讀不懂就略過 |
| 開啟方式 | 預設關閉，每批多出約一半的請求數 |

小模型批次翻譯時，常把一句的內容寫到隔壁句。先重述再比對，是 PoC 實測較穩定的判斷方式；判斷翻譯是否完整的做法誤判太多，已經放棄。

### 9.7 串流呈現

```
  第 1 批：翻譯 ─▶ 自我修復 ─▶ 自我檢查 ─▶ 寫進目前資源 ─▶ 畫面顯示
  第 2 批：……
  最後一批完成 ─▶ 寫出 [name].[lang].srt
```

修復與檢查都在同一批之內完成，所以每批顯示的就是定稿，之後不會再改寫。翻譯中途失敗時，已顯示的譯文留在畫面上但不寫檔，避免留下只翻一半的檔案。翻譯中換了專案，後續的批次不寫回。

## 10 字幕校對與匯出

相依：第 1、2、6 章，校對的對象是目前資源的字幕。

### 10.1 預覽與時間軸

```
  ┌ 預覽 ──────┬ 控制卡片 ──────────────────┐
  │ 影片，疊字  │ 播放、目前段落的時間與文字 │
  ├ 時間軸（全寬）─────────────────────────────┤
  │ 波形，段落區段交錯                        │◀─┐ 選取同一段
  └───────────────────────────────────────────┘  │
  ┌ 段落清單（全寬）──────────────────────────┐  │
  │ 目前段落：空白鍵只播這一段                │◀─┘
  └───────────────────────────────────────────┘
```

| 需要 | 做法 |
|---|---|
| 邊聽邊改 | 預覽與時間軸在清單上方 |
| 用上寬度 | 影片與卡片分寬，波形全寬 |
| 小螢幕 | 可收起預覽，只留清單 |
| 聽清楚一句 | 空白鍵只播選取的段落 |
| 看出切段 | 波形上段落兩色交錯 |
| 長檔案 | Rust 以 ffmpeg 算波形 |
| 本機檔案 | 只開放專案目錄 |
| 播不了的格式 | 仍顯示波形 |

校對時要反覆聽同一句，所以單句播放不需要點按鈕。波形在 webview 解碼整段音訊會佔大量記憶體，交給 Rust 以內建的 ffmpeg 計算。拖動邊界改時間是之後的功能。

### 10.2 編輯

| 可以改 | 狀態 |
|---|---|
| 原文與譯文 | 已有 |
| 說話者 | 已有；從已用過或詞彙表的說話者挑選，或輸入新的名稱並可加入詞彙表；改動寫到每一種譯文 |
| 時間戳 | 已有：直接改開始與結束時間，勾選多段一起平移；之後在 10.1 的時間軸拖動 |
| 新增、刪除、合併、切割段落 | 已有：每段選單可在上下方新增、刪除、在游標處切割；勾選相鄰多段可合併 |

whisper 的切段常需手動修正，調整時間戳與段落是校對重點。譯文依時間對上原文，所以這些改動一律寫回原文與每種譯文。說話者以原文為準，同步只改標籤，對不上的譯文不會被刪。

| 對照 | 做法 |
|---|---|
| 備份 | 原文與顯示中的譯文可同時各比較一份備份，差異標在各自的欄位 |
| 其他譯文 | 可同時勾選多種，唯讀疊在每段下方 |
| 版面 | 一律上下疊，窄螢幕也放得下；分欄是之後的選項 |

校對時要同時看原文改了什麼、譯文跟著改了什麼，也常參考其他語言的譯法。

### 10.3 匯出

| 選項 | 內容 | 沒有譯文時 | 預設檔名 |
|---|---|---|---|
| 雙語 SRT | 依 1.3 的格式 | 停用 | `ep01.zh-TW.en.srt`；譯文在上時 `ep01.en.zh-TW.srt` |
| 另存原文 | 原文與說話者 | 可用 | `ep01.srt` |
| 另存譯文 | 目前譯文與說話者 | 停用 | `ep01.en.srt` |

原文與譯文已經自動寫回專案目錄（2.4），匯出只負責目錄裡沒有的雙語 SRT，以及存到其他地方。對話方塊預設開在專案目錄，檔名是資源名稱加上語言代碼。

### 10.4 編輯欄位

| 需要 | 做法 |
|---|---|
| 只收純文字 | `contenteditable="plaintext-only"`，字幕沒有格式 |
| 標記不寫進內容 | CSS Custom Highlight 以範圍著色，欄位值始終是字幕原文 |
| 不支援 Highlight | 只顯示備份的文字，不標在欄位裡 |
| 與 Stimulus 搭配 | 欄位本身是不綁定框架的模組，每個欄位由一個 controller 接上 |

textarea 不能在文字裡標記，後續的詞彙標記與選取都需要。ProseMirror、CodeMirror 為文件或程式碼設計，與逐段的字幕差太多，所以從原生元素做起。

## 11 介面

相依：第 2、6～10 章，畫面呈現專案、流程與各模組。

### 11.1 視窗

| 情況 | 大小 |
|---|---|
| 首次開啟 | 佔螢幕可用範圍 80% |
| 取不到螢幕大小 | 1200×900 |
| 再次開啟 | 還原上次關閉時的大小與位置 |

編輯畫面要並排資源清單、影片預覽與段落清單，800×600 放不下；取不到螢幕大小時，把它放大 1.5 倍。

### 11.2 畫面分工

```
  ┌───────────────────────────────────────────────────────┐
  │ lecture ▾        [轉錄] [翻譯]  [匯出 ▾]  [設定]    │  工具列
  ├────────────┬──────────────────────────────────────────┤
  │ 資源清單   │ 字幕編輯：預覽、時間軸、段落清單         │
  └────────────┴──────────────────────────────────────────┘
       轉錄、翻譯、設定、詞彙表 ─▶ modal，關閉後回到編輯
```

| 畫面 | 內容 |
|---|---|
| 起始 | 沒有開啟專案時：開啟目錄、開啟 SRT、最近的專案 |
| 資源清單 | 專案內各資源與字幕狀態、開啟翻譯詞彙表 |
| 字幕編輯 | 目前資源的預覽、段落、任務進度與逐步出現的結果 |
| 任務 modal | 轉錄或翻譯選項、開始按鈕；轉錄後翻譯時兩者都在 |
| 詞彙表 modal | 以表格編輯 `glossary.csv` |
| 設定 modal | 分成專案與整體兩頁：專案頁放主語言、雙語順序等只影響這個目錄的設定；整體頁放元件、模型與翻譯參數。每項都有說明 |

編輯是唯一的主畫面，任務與設定都是暫時蓋在上面的 modal。工具列放專案層級的動作。各畫面的配置見 `docs/ui.md`。

### 11.3 多語系

| 規則 | 說明 |
|---|---|
| 預設語言 | 使用系統語言 |
| 沒有對應的翻譯 | 使用英文 |
| 手動切換 | 在設定改介面語言 |
| 文字來源 | 後端只送代碼與資料，文字由前端依語言產生 |

後端以代碼與資料回報錯誤（Failure），只有前端產生介面文字。系統語言由作業系統回報，因為 WebView2 的 `navigator.language` 不會隨 Windows 的語言設定改變。

### 11.4 樣式

| 項目 | 設計 |
|---|---|
| 樣式工具 | TailwindCSS，隨前端一起由 Vite 建置 |
| 元件樣式 | daisyUI，以 Tailwind 外掛提供元件 class 與主題色 |
| 與 Stimulus 的分工 | Stimulus 管互動，Tailwind 的 class 寫在 HTML 上 |

畫面變多之後，手寫 CSS 難以維持一致。樣式跟著 HTML 走，controller 不需要知道樣式。元件與顏色取自 daisyUI，各畫面共用同一套外觀。

## 13 建置與釋出

相依：全部章節，打包的是前面各章的成果。

### 13.1 CI

```
  push、PR ─▶ spec（sumi）
           ├▶ licenses（cargo-deny、cargo-about）
           ├▶ frontend（Vitest、型別檢查）
           └▶ rust × 3 平台（fmt、clippy、test）
                   │ 全部通過，且是 push main 或手動觸發
                   ▼
              build × 3 平台
                   │ 每個元件的內建變體（build-component action）
                   │   cache 命中就還原，否則以 vendor.sh 編譯
                   │   確認能回應版本參數
                   ▼
              打包 ─▶ 上傳產物
```

action 釘 commit SHA，下載的工具釘 SHA256。Rust cache 以編譯器版本與 lockfile 為 key，存檔前移除會重新編譯的產物。元件 cache 以平台、變體、該元件的釘版與建置腳本為 key，只重編改到的元件；cache 過期時由 GitHub 清除，下次打包重新編譯。

### 13.2 產物與授權聲明

| 平台 | 產物 |
|---|---|
| Windows | `tsuzuri.exe`、NSIS 安裝檔、MSI |
| macOS | dmg、`.app` |
| Linux | 各種安裝包 |
| 全部 | `THIRD-PARTY-LICENSES.html`、`THIRD-PARTY-LICENSES-WEBVIEW.html` |

兩份授權聲明分別涵蓋 Rust 相依與 webview 打包的套件（4.4）。

### 13.3 釋出流程

```
  合併到 main ─▶ release-please 更新版本 PR
  合併版本 PR ─▶ 建立 tag 與 GitHub Release
              ─▶ CI 打包並附上產物、ffmpeg 原始程式碼、更新資訊
```

版號與 changelog 由 release-please 管理。不做作業系統的程式碼簽章；macOS 與 Windows 的放行步驟寫在 `README.md` 與 `README.zh-TW.md`。

### 13.4 自動更新

| 事項 | 設計 |
|---|---|
| 機制 | Tauri updater plugin |
| 更新來源 | GitHub Release 附帶的更新資訊檔 |
| 簽章 | updater 強制驗證更新檔；用 Tauri 自己的金鑰，私鑰放在 CI secret |

updater 用自己的金鑰簽章，跟作業系統要求的程式碼簽章無關，所以不做程式碼簽章也能自動更新。

## 14 風險與待驗證

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| Windows 專屬程式碼沒有自動測試 | 殘留行程清理可能失效 | Windows 實機測試；補 Windows 測試 |
| CSP 關閉 | 少一層防護 | 設定 CSP 後確認介面正常 |
| Vulkan、OpenBLAS 變體實際多快 | 自動選擇順序可能要調整 | 在不同硬體上量 RTF |
| Linux 系統函式庫 | 缺 libgomp1、libvulkan1 時跑不起來 | `.deb` 宣告相依 |
| 沒有支援 Vulkan 的驅動 | 內建的 whisper-cli、llama-server 無法執行 | 顯示無法執行，使用者指定 CPU 版；自動選擇上線後改為自動退回 |
| 殘留行程只比對名稱 | PID 重用時可能誤殺同名行程 | 評估是否加上啟動時間比對 |
| macOS 產物只有 linker 產生的 ad-hoc 簽章，且不完整 | 下載後顯示「已損毀」，沒有「強制打開」可選，只能用 `xattr` 移除隔離標記 | 打包時以 `signingIdentity: "-"` 完整 ad-hoc 簽章後，確認出現「強制打開」 |
| updater 私鑰遺失 | 已安裝的版本無法再自動更新 | 在 CI 以外另存私鑰備份 |
| 說話者取開頭到第一個冒號為止，不限長度 | Netflix 繁中指南的 `我問：「…」`、`日期：…`、`導演：…` 也會被當成說話者；寫出時冒號統一為 `: ` | 收集實際字幕檢查誤判；長度限制擋不住這些短句，故不採用 |
| 說話者辨識工具未定 | 可能超出 4GB VRAM，或授權不允許散布 | 依 8.2 的條件評估候選工具 |

這些風險不阻擋目前的開發，但正式釋出前要逐一處理或接受。
