# Tsuzuri 設計

Tsuzuri（綴り）在本機把影片與音訊轉成字幕，並提供翻譯與校對，音訊與文字不離開使用者的電腦。它為有隱私需求、不能上傳雲端的情境而生。這份文件記錄設計的意圖與取捨，行為與介面的細節以 `.spec/` 為準。

## 0 總覽

### 0.1 設計承諾

| 承諾 | 意義 |
|---|---|
| 本機處理 | 音訊與文字不離開電腦 |
| 元件內建且可覆寫 | 使用者指定的優先 |
| 一次只載入一個模型 | 4GB VRAM 也能用 |
| 不留下行程 | 當掉也不佔記憶體或 port |
| 流程由使用者組合 | 模式只是預設組合 |

網路只用於首次設定、更新與使用者主動下載。安裝檔內建能在各平台執行的元件。各 Step 依序執行，前一個模型釋放才載入下一個。轉錄、說話者辨識與翻譯是模組。這五項是設計的固定點，兩項衝突時由該章說明哪一項讓步。

### 0.2 系統分層

| 意圖 | 做法 |
|---|---|
| 單一事實來源 | 資料都在 Rust |
| 介面不被拖慢 | 處理留在 Rust |
| 當掉不影響介面 | 運算在子行程 |

Webview 顯示的資料都向 Rust 查詢，變更也都寫進 Rust，自己只負責畫面、互動與多語系。GPU 或記憶體出問題只結束該元件行程。分層、模組與相依規則見 `docs/architecture.md`。

## 1 字幕資料

所有模組都讀寫同一種資料，沒有相依。

行為：`transcript.md`。

### 1.1 Segment 與 Transcript

| 概念 | 內容 |
|---|---|
| Segment | 一段語音 |
| Transcript | 依時間排的 Segment |
| 譯文 | 一次一種語言 |
| 多語言對照 | 尚不需要 |

Segment 有開始、結束時間、可省略的說話者與文字，譯文靠時間對上原文。Transcript 是單一媒體檔的全部 Segment。模組之間只交換 Transcript，不交換元件自己的格式，所以轉錄可以換引擎、翻譯可以接既有字幕，不影響其他模組。

### 1.2 SRT 讀寫

| 情況 | 處理 |
|---|---|
| BOM | 讀入清除，寫出不帶 |
| CRLF | 讀入時與 LF 相同 |
| 說話者 | 第一行開頭的 `標籤:` |
| 一段文字有多行 | 保留換行 |
| 時間格式錯誤 | 失敗，並指出是第幾段 |
| 文字含空行 | 寫出時移除 |

SRT 是 Transcript 唯一的交換格式，whisper-cli 輸出與使用者提供的檔案都用它，純文字只供匯出（10.5）。BOM 會讓有些播放器亂碼，空行會把一段切成兩段。標籤只在其他行都沒有時才算說話者，寫出時加回，譯文用詞彙表的名稱（9.3）；讀入譯文只去掉原文的標籤。

### 1.3 雙語 SRT

```
  1
  00:00:01,000 --> 00:00:03,500
  CO: 今天我們來談隱私               ← 原文（預設在上）
  CO: Today we talk about privacy    ← 譯文
```

| 情況 | 處理 |
|---|---|
| 順序 | 預設原文在上 |
| 說話者 | 各自語言的名稱 |
| 某段沒有譯文 | 只寫出原文 |
| 讀入雙語 SRT | 使用者選擇是否拆開 |

一份字幕顯示兩種語言，播放器不需額外支援。專案設定可改成譯文在上，檔名的語言代碼也依此順序；說話者沒有另外命名時兩行相同。有些字幕本身就換行，分不出是否雙語，所以讀入時由使用者決定，預設整段當原文。

## 2 專案

專案對應一個目錄，收納同一系列作品的媒體檔、字幕與設定，例如一部作品的各集。相依：第 1 章。

行為：`project.md`、`versions.md`、`undo.md`。

### 2.1 專案目錄

```
  lecture/                     ← 專案
  ├── tsuzuri.config.json      ← 專案設定（2.3）
  ├── glossary.csv             ← 翻譯詞彙表（9.3）
  ├── .tsuzuri/history/        ← 產出與覆蓋前的備份（2.5），不當成資源
  ├── ep01.mp4  ┐
  ├── ep01.srt  ├ 資源 ep01：媒體檔、主語言字幕、en 譯文
  ├── ep01.en.srt ┘
  ├── ep02.mp4                 ← 資源 ep02：只有媒體檔，可以轉錄
  └── ep03.srt                 ← 資源 ep03：只有字幕，可以編輯與翻譯
```

| 概念 | 內容 |
|---|---|
| 資源 | 同檔名的媒體檔與字幕 |
| 目前資源 | 編輯畫面與任務的對象，一次一個 |

資源是一集或一段錄音。目錄就是事實來源，Tsuzuri 不另外儲存字幕的副本。只有字幕的資源就是單純編輯字幕。

### 2.2 資源配對

| 代號 | 意義 |
|---|---|
| `n` | 資源名稱 |
| `p` | 主語言代碼 |
| `l` | 其他語言代碼 |
| `x` | 不認得的代碼 |

| 檔案 | 角色 |
|---|---|
| `n` 加媒體副檔名 | 媒體檔 |
| `n.srt` | 主語言字幕 |
| `n.p.srt` | 主語言字幕，次於 `n.srt` |
| `n.l.srt` | `l` 譯文 |
| `n.l.l.srt` | 雙語匯出，不載入 |
| `n.x.srt` | 有資源 `n` 時不載入 |

| 順序 | 做法 |
|---|---|
| 1 | 媒體檔與 `n.srt` 定出名稱 |
| 2 | 其餘由短到長對上名稱 |
| 3 | 對不上的 `n.p.srt` 開新資源 |
| 4 | 對不上的 `n.x.srt` 當成名稱 |

媒體副檔名是內建 ffmpeg 能解的容器，如 `.mp4`、`.mkv`、`.m4a`。名稱可以像 `talk.hd` 帶著像代碼的結尾；`n.l` 本身是資源時，`n.l.l.srt` 是它的譯文。譯文依時間對上段落，一次編輯一種。

### 2.3 專案設定

| 設定 | 沒有設定檔時 |
|---|---|
| 名稱 | 目錄名稱 |
| 主語言 | 依介面語言 |
| 翻譯語言 | 未指定；翻譯後記下 |
| 雙語順序 | 原文在上（1.3） |
| 自動儲存雙語 | 關閉 |
| 覆蓋前備份 | 關閉 |
| 專案模型 | 依整體設定（5.6） |
| 轉錄設定 | 依整體設定（7.4） |

```
  軟體設定（預設值） ─▶ 專案設定（覆寫） ─▶ 任務的選項（只用這一次）
```

專案設定存在 `tsuzuri.config.json`，第一次改動時建立。介面是正體中文時主語言預設 `zh-TW`，其他為 `en`。主語言在設定畫面修改，轉錄與翻譯都以它為原文語言。

### 2.4 寫回

| 時機 | 寫入 |
|---|---|
| 編輯原文 | 主語言字幕 |
| 編輯譯文 | 目前的譯文 |
| 編輯說話者 | 原文與每種譯文 |
| 轉錄完成 | `[name].srt` |
| 翻譯完成 | `[name].[lang].srt` |
| 自動儲存雙語 | `[name].[a].[b].srt` |

自動寫回讓關掉 App 不會遺失結果，字幕也直接能交給播放器。說話者依時間帶到每種譯文，對不上的不動；轉錄寫出後只寫入有改變的譯文。自動儲存雙語開啟時，寫出原文更新每種雙語檔，寫出譯文只更新那一種。

### 2.5 備份與復原

| 情況 | 做法 |
|---|---|
| 任務寫出後 | 留成產出備份 |
| 覆蓋前備份開啟 | 任務覆蓋前先複製 |
| 開啟後首次改動 | 先留一份覆蓋前備份 |
| 還原備份 | 先備份目前的再取代 |
| 每次改動前 | 記下一步，最多 100 |
| 外部改過或配對改變 | 清掉復原紀錄 |
| 關閉專案 | 復原紀錄不留 |
| 轉錄中 | 鎖住整個資源 |
| 翻譯中 | 只鎖那份譯文 |
| 重譯中 | 只鎖勾選的段落 |

備份在 `.tsuzuri/history/`，名為 `[name][.lang].[UTC].output.srt`，覆蓋前的沒有 `.output`，產出備份是比較的對象。編輯與重譯靠復原紀錄，每次開啟只多留一份備份。任務進度只顯示，取消就回到檔案的內容。

### 2.6 開啟與重讀

| 情況 | 做法 |
|---|---|
| 開啟目錄 | 掃描資源，選第一個 |
| 開啟 SRT | 開它的目錄並選取 |
| 任務中開啟 | 拒絕，請使用者等待 |
| 從檔案總管開啟 SRT | 同開啟 SRT |
| 已執行時再開啟 | 交給執行中的視窗 |
| 切回視窗 | 外部改過就重新載入並告知 |
| 按重新載入 | 重新配對目錄，重讀目前資源 |
| 寫回前內容不同 | 重讀，不寫入並告知 |
| 復原前內容不同 | 同寫回前 |
| 任務中外部改過 | 兩邊都留，照常寫出 |

字幕常在專業字幕軟體裡再修，所以寫回前先比對內容，不蓋掉外部的修正；被取代的一方先留成備份。原文時間被改過時，譯文照寫並提示對不上的句數。不比對修改時間，因為有些檔案系統的時間不夠精細。

### 2.7 最近的專案

| 欄位 | 內容 |
|---|---|
| 名稱 | 專案名稱（2.3） |
| 路徑 | 目錄完整路徑 |
| 開啟時間 | 最近一次開啟時間 |

| 情況 | 做法 |
|---|---|
| 開啟成功 | 記下或更新時間 |
| 超過 10 筆 | 移除最舊的 |
| 目錄已不存在 | 開啟失敗時移除 |
| 顯示在開啟選單 | 不列目前的專案 |

每個目錄一筆，記在軟體設定裡，開 SRT 時記它所在的目錄。清單顯示在起始畫面與開啟選單（11.2）。權限不足等其他失敗不移除，暫時連不上的磁碟再接上仍能開。名稱逾時未讀到就用目錄名稱，清單不被磁碟卡住。

## 3 行程

元件以子行程執行，沒有相依。

行為：`processes.md`、`observability.md`。

### 3.1 啟動與紀錄

```
  Processes::spawn(絕對路徑)
    ├ 記錄 PID 與執行檔名稱到 app data
    ├ 轉送 stdout、stderr 給呼叫端，並逐行寫入 log
    └ 行程結束 → 從紀錄移除
```

一律以絕對路徑啟動，不用 Tauri 的 sidecar，因為元件未必來自安裝檔。元件直接由 App 啟動且不再開子行程，所以紀錄涵蓋全部行程。log 同時印到終端機與寫入檔案，預設在系統的 log 目錄（macOS 是 `~/Library/Logs/me.aotoki.tsuzuri/`），設定頁可改目錄、開除錯紀錄，重新啟動後生效。

### 3.2 清理

| 情境 | 機制 |
|---|---|
| App 正常結束 | 在 `RunEvent::Exit` kill 仍在執行的子行程 |
| App 當掉或被強制結束 | 下次啟動時清理 |
| PID 已被其他程式重用 | 名稱不符就不動它 |

下次啟動時 kill 紀錄中還活著且名稱相符的行程，Windows 用 `taskkill /T /F`。`tauri-plugin-shell` 只清理從 JS 端啟動的行程，所以 App 自己負責 Rust 端啟動的行程。當掉後的殘留會佔著 VRAM 直到下次啟動。

## 4 元件

相依：第 3 章，元件以行程執行。

行為：`components.md`、`licenses.md`。

### 4.1 尋找順序

```
  使用者指定的執行檔（例如 CUDA 版）
        │ 沒有，或檔案不在
        ▼
  偵測已安裝的版本（PATH、Homebrew、Nix；要能回應版本參數）
        │ 找不到
        ▼
  安裝檔內建的變體（依 0.4 自動選擇）
        │ 沒有
        ▼
  提示怎麼安裝
```

使用者指定的永遠優先，這是 CUDA 等進階設定的入口。macOS 的 App 讀不到 shell 的 PATH，所以常見的安裝目錄逐一列出。

### 4.2 內建變體

| 元件 | 變體 | 理由 |
|---|---|---|
| whisper.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 上游會刪舊 nightly |
| llama.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 與 whisper.cpp 一致 |
| ffmpeg | 純音訊的 LGPL 版 | 只需解出音軌，範圍小、授權單純 |

App 不在執行時下載元件。內建變體放在 `components/<元件>/<變體>/`，App 照 Build Manifest 列出的順序逐一嘗試，採用第一個能執行的變體；選擇結果顯示在設定頁，可以手動改。目前安裝檔只內建第一個變體，其他變體與 CUDA 版由使用者依 12.2 指定。

### 4.3 自行編譯

| 平台 | GitHub Actions 編譯環境 |
|---|---|
| Windows | Windows runner，MSYS2 UCRT64 編譯，附執行所需 DLL |
| Linux | Linux runner，用系統的 OpenBLAS、Vulkan 函式庫 |
| macOS | macOS runner，靜態連結 |

原始程式碼的版本、SHA256 與各平台的變體記在 `components.json`（Build Manifest），CI 與開發機跑同一支 `scripts/vendor.sh`。ffmpeg 的 `configure` 在 Windows 需要 MSYS2，所以 Windows 全部在那裡編譯。`vendor/` 與安裝檔同樣是 `<元件>/<變體>/` 的結構，開發時的 debug build 會先偵測它；打包時合併 `tauri.bundle.conf.json`，把 `vendor/` 放進安裝檔的 resources。

### 4.4 授權

| 對象 | 授權 | 做法 |
|---|---|---|
| whisper.cpp、llama.cpp | MIT | 收進授權頁 |
| llama 編入的函式庫 | MIT | 收進授權頁 |
| ffmpeg | LGPL 2.1+ | 收進授權頁、附原始程式碼 |
| Windows 的 DLL | GCC 例外等 | 收進授權頁 |
| Rust 相依套件 | 見 `deny.toml` | cargo-deny 檢查 |
| Webview 打包套件 | 同 `about.toml` | 腳本檢查 |
| OpenCC 字典 | Apache-2.0 | 收進授權頁 |

`vendor.sh` 把每個變體帶著的授權檔放進 `licenses/`，`scripts/licenses.ts` 再把全部寫成授權頁，從設定的「關於」開啟（`docs/ui.md` 7.6）。ffmpeg 不開 GPL、nonfree，是獨立執行檔，原始程式碼附在每次釋出。

## 5 模型

模型從預設清單或 Hugging Face 下載，也可以指定本機檔案，沒有相依。

行為：`models.md`。

### 5.1 來源

| 來源 | 記下 | 檔案在 |
|---|---|---|
| 預設模型 | repo、檔名、commit | HF 快取 |
| HF Repository | repo、檔名、commit | HF 快取 |
| 本機檔案 | 路徑 | 使用者指定處 |

每個 Model Slot 記的是來源而不是路徑，專案設定換到另一台電腦也找得回同一個檔案，檔案不見時可以重新下載。只記路徑的舊設定當成本機檔案讀入。

### 5.2 預設模型

| 用途 | 模型 | Repository |
|---|---|---|
| 轉錄 | Breeze-ASR-25 | `tsuzuri-app/…` |
| 轉錄 | Whisper large-v3-turbo | `ggerganov/whisper.cpp` |
| 轉錄 | Whisper large-v3 | 同上 |
| 翻譯 | Qwen3-4B-Instruct-2507 | `unsloth/…-GGUF` |
| VAD | Silero v6.2.0 | `ggml-org/whisper-vad` |

已驗證的模型列成清單，使用者不必知道去哪裡找。Breeze 只適合中文，Whisper 支援多語言，翻譯的 0.8B 等級品質不足。各列附數種量化，commit 釘在 Rust，和元件的釘版一樣。

### 5.3 下載與快取

| 情況 | 做法 |
|---|---|
| 快取已有 | 不連網，直接使用 |
| 快取沒有 | 下載並顯示進度 |
| 取消或失敗 | 不改設定 |
| 需要登入 | 提示先以 hf 登入 |
| 任務進行中 | 照常下載 |
| Windows | 沿用 hf-hub 的複製 |

快取位置依 `HF_HUB_CACHE`、`HF_HOME`，否則是 `~/.cache/huggingface/hub`，與其他 HF 工具共用，下載過的不再下載。token 只取自 HF 工具的登入，App 不保存秘密。Windows 上 hf-hub 以複製代替 symlink，模型會佔兩倍空間，沿用這個預設行為。

### 5.4 Repository 的檔案

| Model Slot | 列出的檔案 |
|---|---|
| 轉錄 | `.bin`，除了 VAD |
| VAD | `ggml-silero*.bin` |
| 翻譯 | `.gguf` |

輸入 `owner/name` 後列出檔案與大小，只顯示這個 Model Slot 能用的格式。whisper.cpp 的轉錄與 VAD 模型都是 `.bin`，只能以檔名區分。

### 5.5 檢查

| 情況 | 做法 |
|---|---|
| 沒有指定 | 不啟動，提示指定 |
| 本機檔案不在 | 提示重新指定 |
| 快取裡沒有 | 提示重新下載 |

啟動引擎前確認檔案還在，不在就不啟動引擎。模型不寫進元件清單，下載只在使用者選擇時發生。

### 5.6 專案模型

| 情況 | 使用的模型 |
|---|---|
| 專案有指定 | 專案模型 |
| 專案沒有指定 | 整體設定的模型 |
| 檔案不在 | 依 5.5 處理 |

專案語言不同，適合的轉錄與翻譯模型也不同，例如中文與日文。專案模型以同樣的來源記在專案設定，切換專案不必重選。VAD 模型與語言無關，只在整體設定指定。

## 6 工作流程

相依：第 1、3～5 章，流程串起的模組需要字幕資料、行程、元件與模型。

### 6.1 模組與流程

```
  媒體檔 ─▶ [轉錄模組] ─┐
                        ▼
  SRT 檔 ───────────▶ Transcript ─▶ [說話者辨識模組] ─▶ [翻譯模組]
                                     可選，需要媒體檔        │
                                                             ▼
                                                  Transcript（含譯文）
```

模組以 Transcript 為輸入或輸出，使用者可以組合它們。流程依序執行，前一個模組的行程全部結束後，下一個才開始。

### 6.2 任務

```
  字幕編輯（目前資源）
    ├─ [轉錄] ─▶ 轉錄模組 ─┬─▶ 段落逐段出現在編輯畫面
    │                        └─ 勾選完成後翻譯 ─┐
    └─ [翻譯] ─────────────────────────────────┴─▶ 翻譯模組 ─▶ 譯文逐批出現
```

| 任務 | 組成 | 可以開始的資源 |
|---|---|---|
| 轉錄 | 轉錄模組 | 有媒體檔 |
| 翻譯 | 翻譯模組 | 有主語言字幕 |
| 轉錄後翻譯 | 轉錄模組 → 翻譯模組 | 有媒體檔 |
| 局部轉錄（7.5） | 轉錄模組，可接翻譯 | 有媒體檔與字幕 |

編輯畫面是基本狀態，任務從 modal 開始，一次一個。任務寫入的字幕進行中不能改，結果算一步復原（2.5）。轉錄後接著翻譯時，轉錄的 modal 也列出翻譯選項。組合目前寫死在程式裡，改成可組合後變成內建範本。

### 6.3 進度與取消

| 規則 | 說明 |
|---|---|
| 每個模組回報進度 | 名稱、百分比，能算就附 N／M |
| Phase 序列 | 標出走過與目前的 |
| 算不出進度時 | 顯示不定進度，例如載入模型 |
| 顯示位置 | 編輯畫面上方 |
| 取消 | 結束行程，不寫檔 |

結果在同一畫面逐步出現，結束後進度消失，完成或失敗改以通知告知；取消時已顯示的留在畫面。Metal shader 第一次載入才編譯，冷啟動約 30 秒，偵測 llama-server 也會觸發。轉檔仍沒有百分比。

### 6.4 模型的狀態

```
            翻譯開始                          翻譯結束
  [空閒] ──────────▶ [載入翻譯模型] ──▶ [翻譯中] ──────▶ [保留 N 秒]
    ▲  ▲                                                   │    │
    │  └──────────────── 時間到，釋放 ──────────────────────┘    │
    │          轉錄結束                               轉錄開始，先釋放
    └──────────────────── [轉錄中] ◀───────────────────────────┘
  [空閒] ── 轉錄開始 ──────▶ [轉錄中]
```

| 規則 | 做法 |
|---|---|
| 一次一個任務 | 同一把鎖，後來的排隊 |
| 轉錄開始 | 先釋放翻譯模型，不行就停止 llama-server |
| 保留期間再翻譯 | 取消排定的釋放，沿用載入的模型 |

轉錄、翻譯與關掉常駐都先取得同一把鎖，不打斷進行中的任務。目前以這把鎖守住這些轉移，沒有明確的狀態列舉。流程改成可組合時，再把狀態與轉移寫成狀態機。

## 7 轉錄模組

相依：第 6 章，以模組身分加入流程。

行為：`transcribe.md`。

### 7.1 Step

```
  媒體檔 ─▶ ffmpeg ─▶ 16kHz 單聲道 WAV ─▶ whisper-cli ─▶ SRT ─▶ Transcript
```

先轉成統一格式，轉檔失敗與轉錄失敗可以分開診斷。兩個 Step 依序執行，whisper-cli 結束即釋放記憶體。

### 7.2 語言

| 設定 | 設計 |
|---|---|
| 轉錄語言 | 專案的主語言（2.3）；傳給 whisper-cli 的 `-l` |
| 語言清單 | zh-TW、en、ja，與翻譯共用 |
| 模型建議 | 依語言建議模型；Breeze-ASR-25 只適合中文 |

轉錄結果寫成主語言字幕，所以語言跟著專案，不在任務裡另選。每個代碼對各元件的意義只記在 Rust。模型建議尚未決定，目前各語言專案用各自的專案模型（5.6）。

### 7.3 進度與串流

| 來源 | 內容 |
|---|---|
| stderr `main: processing` | 模型載入完成，開始轉錄 |
| stderr `progress = N%`（`-pp`） | 轉錄的百分比 |
| stdout `[開始 --> 結束]  文字` | 剛轉錄完成的段落 |
| 輸出 SRT | 結束時定稿，取代逐段累積的段落 |

whisper-cli 每處理約 30 秒的音訊就送出一批段落與百分比，經過 pipe 也不延到結束。段落逐批加進目前資源，最後一段後留一列 skeleton。完成時回報音檔長度與耗時以算出 RTF。

### 7.4 轉錄設定

| 設定 | whisper-cli | 預設 |
|---|---|---|
| VAD | `--vad -vm` | 關 |
| 抑制非語音 | `-sns` | 關 |
| 延續上文 | 關閉時 `-mc 0` | 開 |
| 清理簡體 | zh-TW 寫入前，見 10.14 | 開 |

預設維持 whisper-cli 原本的行為。靜音與背景音樂容易讓模型寫出沒人說的話，上文又把它帶進下一段而重複，日文模型尤其明顯。VAD 先略過沒有語音的片段，其餘兩項切斷重複。專案可逐項覆寫。

### 7.5 局部轉錄

```
  字幕      ─[A]─[B]─[C]─[D]─[E]─
  窗口               ▲ C 開始 ──▶ D 結束或媒體結尾
  ffmpeg             只轉出窗口內的音訊
  寫回      ─[A]─[B]─[新段落…]─[E]─   先備份
```

| 入口 | 窗口 |
|---|---|
| 以下重新轉錄 | 該段開始到結尾 |
| 重新轉錄此範圍 | 勾選段的頭到尾 |
| 被取代的段落 | 開始時間在窗口內 |

使用者修好的段落不動，只重做窗口內的。ffmpeg 切出窗口，時間再加回起點；whisper-cli 的 `-d` 不會停在長度，搭配 VAD 時 `-ot` 的時間也會錯。寫回與整份轉錄相同。

## 8 說話者辨識模組

相依：第 6、7 章，以模組身分加入流程，需要轉錄產出的 Transcript。

### 8.1 Step

```
  媒體檔、Transcript ─▶ [說話者辨識] ─▶ 標上說話者的 Transcript
```

| 規則 | 說明 |
|---|---|
| 輸入 | 媒體檔與轉錄產出 Transcript |
| 輸出 | 每個 Segment 標上說話者 |
| 開啟方式 | 專案設定或執行時選擇，預設關閉 |

whisper.cpp 不支援說話者辨識，所以在轉錄之後另外辨識。辨識與對應說話者的做法尚未決定。

### 8.2 工具選擇

| 條件 | 理由 |
|---|---|
| 在本機執行 | 設計承諾「本機處理」 |
| 結束即釋放記憶體 | 設計承諾「一次只載入一個模型」 |
| 授權允許隨 App 散布 | 同第 4.4 章的元件 |

候選工具尚待評估，這三項是選擇時的最低條件。

## 9 翻譯模組

相依：第 6 章，以模組身分加入流程。機制參考翻譯 PoC（qwen-translator-script），它針對小模型常見的漏翻、重複、跨句錯位設計了分層的修復。

行為：`translate.md`、`glossary.md`。

### 9.1 llama-server 生命週期

```
  App 啟動 ─▶ 背景啟動 router，不載入模型
  翻譯開始 ─▶ /models/load ─▶ 等到載入完成 ─▶ 送出各批翻譯
  翻譯結束 ─▶ 保留 N 秒 ─▶ /models/unload
  App 結束 ─▶ 停止 router 與它的模型行程
```

| 請求 | 做法 |
|---|---|
| 介面 | OpenAI 相容的 chat completions，以 async-openai 送出 |
| 內容 | 一批句子，各帶 index |
| 回應 | 以 JSON schema 限定格式，依 index 對回各句 |
| 思考模式 | 以 `chat-template-kwargs` 關閉，翻字幕用不到 |

| 常駐 | 做法 |
|---|---|
| 模型與參數 | Tsuzuri 寫的 preset |
| 一次一個 | `--models-max 1`、`--no-models-autoload`，只在翻譯開始時載入 |
| 保留 N 秒 | Tsuzuri 計時，預設 0，改了不重啟 router |
| 轉錄開始 | 先釋放翻譯模型 |
| 關掉常駐 | 每次翻譯才啟動 |
| router 意外結束 | 下一次翻譯重新啟動 |

請求附上前一批最後幾句的原文與譯文當參考。preset 記模型路徑、context 4096 與關閉思考，換模型時重讀；context 固定避免撐爆 VRAM。常駐省下啟動與關閉行程，router 不載入模型時不佔記憶體。

### 9.2 分批

| 規則 | 說明 |
|---|---|
| 每批數句 | PoC 預設 8 句，請求比逐句少很多 |
| 同一句不拆開 | 被切成多段的一句話排在同一批 |
| 失敗就拆半 | 重試仍失敗就拆兩半 |
| 說話者標籤 | 只送對話，待第 8 章開放 |

```
  以重疊兩句的視窗請模型找出被切開的句子 ─▶ 同一句排進同一批 ─▶ 依序翻譯各批
```

說話者標籤暫不開放；冒號前是純數字的時間不算標籤，譯完行數變了就不接回。偵測在翻譯之前的 detect Phase 依序進行，失敗的視窗略過。串成超過兩倍批次大小的一組就不再保持完整，退回固定分批，避免請求撐爆 context。

### 9.3 詞彙表檔案

| 設定 | 設計 |
|---|---|
| 格式 | CSV，每欄一種語言 |
| 標頭 | 語言代碼 |
| `type` 欄 | 最後一欄，可省略 |
| 來源 | 專案的 `glossary.csv` |
| 編輯 | 詞彙表 modal |

每一列是同一個詞的各語言寫法，例如標頭 `zh-TW,en,ja`；以語言分欄，同一份就能譯成任何語言。`type` 欄的 `speaker` 表示說話者名稱。modal 列出所有支援的語言與說話者勾選，沒有檔案時由此建立。它跟 `.spec/glossary.md` 無關。

### 9.4 詞彙表帶入

| 時機 | 做法 |
|---|---|
| 讀取 | 開專案與每次翻譯前 |
| 對應 | 主語言對目標語言 |
| 帶入 | 只帶該批出現的詞 |
| 檢查 | 不符就重試 |

小模型對陌生的專有名詞容易猜錯，其中一欄空白的列不用。`source,target` 標頭在專案記下翻譯語言時視為主語言與它，否則視為標頭錯誤。重試仍不符就保留最好的版本。說話者名稱也是詞，台詞叫到名字時譯法和標籤一致。

### 9.5 滾動摘要

| 設定 | 設計 |
|---|---|
| 內容 | 限字數的前文摘要 |
| 代價 | 每批多一次請求，PoC 約多 30% 時間 |
| 限制 | 可能錯套人名 |

補足分批只看得到附近幾句的限制。每翻完一批更新一次，失敗就沿用上一版。沒搭配翻譯詞彙表時，模型會把摘要裡的人名錯套到其他人，所以只在有詞彙表時建議開啟。

### 9.6 自我修復

| 偵測到 | 處理 |
|---|---|
| 重複、漏翻、殘留原文、預留字 | 重試；仍失敗就保留原文 |
| 違反翻譯詞彙表、疑似吃掉否定詞 | 重試，仍失敗就留最好的版本 |
| 自我檢查認為譯文屬於鄰句 | 重試，仍失敗就留最好的版本 |
| 回應不是合法 JSON | 附上更正說明重試 |
| llama-server 無法回應 | 停止翻譯，不把原文當成譯文 |

```
  整批送出 ─▶ 有問題的句子帶前後文重試 ─▶ 仍失敗就拆半 ─▶ 剩一句仍失敗就退回
```

確定翻壞就不留下；問題輕微時，寧可保留不完美的譯文。殘留原文只在翻成英文時檢查；否定詞檢查只支援中翻英。

### 9.7 自我檢查

| 設定 | 設計 |
|---|---|
| 做法 | 先重述再指出對應句 |
| 範圍 | 只抓內容跑到鄰句 |
| 開啟方式 | 預設關閉，每批多約一半請求 |

小模型批次翻譯時，常把一句的內容寫到隔壁句。每兩句一次請求，回應讀不懂就略過。先重述再比對，是 PoC 實測較穩定的判斷方式；判斷翻譯是否完整的做法誤判太多，已經放棄。

### 9.8 串流呈現

```
  第 1 批：標為翻譯中 ─▶ 翻譯 ─▶ 修復 ─▶ 檢查 ─▶ 寫進目前資源 ─▶ 畫面顯示
  第 2 批：……
  最後一批完成 ─▶ 寫出 [name].[lang].srt
```

| 時機 | 畫面與檔案 |
|---|---|
| 一批開始 | 它的譯文欄放 skeleton |
| 一批完成 | 顯示定稿 |
| 中途失敗 | 已顯示的留著，不寫檔 |
| 換了專案 | 後續批次不寫回 |
| 譯成 zh-TW | 顯示前清理簡體，可關 |

修復與檢查都在同一批之內完成，所以每批顯示的就是定稿，之後不會再改寫。失敗時不寫檔，避免留下只翻一半的檔案。

### 9.9 重新翻譯

| 設定 | 設計 |
|---|---|
```
  段落        [B] [C] [D] [E] [F]
  斷句         └S1┘     └S2┘
  選的範圍         [C ─── E]
  C 的前文     B 的原文，句子接在它之後
  寫入             只有 C、D、E；S2 同一批
```

| 設定 | 設計 |
|---|---|
| 對象 | 一段或勾選的段落 |
| 語言 | 顯示中的譯文 |
| 斷句偵測 | 範圍與前後一批 |
| 分批 | 範圍內的斷句同批 |
| 前文 | 起頭半句的原文 |
| 參考 | 前 3 句原文與譯文 |
| 後文 | 後 3 句原文，只供理解 |
| 選項 | 自我檢查 |
| 修復 | 沿用 9.6，含詞彙表 |
| 略過 | 滾動摘要 |
| 寫回 | 一步復原，不留備份 |

範圍外是使用者已經修好的，只當參考、不寫入。起頭的半句以原文當前文，減少譯文像在接話；舊譯文已說完整句時仍會發生，由介面提示。它修正的是留過備份的譯文，因此像編輯一樣寫回。

## 10 字幕校對與匯出

相依：第 1、2、6 章，校對的對象是目前資源的字幕。

行為：`editing.md`、`preview.md`；復原見第 2 章。

### 10.1 預覽與時間軸

```
  ┌ 預覽 ──────┬ 控制卡片 ────────────────────┐
  │ 影片，疊字 │ 播放、目前段落的時間與文字   │
  ├ 時間軸（全寬）────────────────────────────┤
  │ 波形，段落區段交錯                        │◀─┐ 同一個目前段落
  └───────────────────────────────────────────┘  │
  ┌ 段落清單（全寬）──────────────────────────┐  │
  │ 目前段落：空白鍵從這段播放                │◀─┘
  └───────────────────────────────────────────┘
```

| 需要 | 做法 |
|---|---|
| 邊聽邊改 | 預覽與時間軸在清單上方 |
| 用上寬度 | 影片與卡片分寬，波形全寬 |
| 看譯文的樣子 | 疊字可換譯文或雙語 |
| 畫面明暗不一 | 疊字底色可選，預設半透明 |
| 確認說話者 | 疊字與目前段落標出 |
| 小螢幕 | 可收起預覽，只留清單 |
| 多螢幕 | 移到影片視窗，見 10.13 |
| 從一句聽下去 | 空白鍵從目前位置播放 |
| 聽清楚一句 | 可開啟只播目前段落 |
| 抓準時間 | 方向鍵移 0.1 秒 |
| 換一句聽 | 點其他列就暫停在那 |
| 邊聽邊改 | 標說話者、換段不停 |
| 播放時看別段 | 可關掉清單追蹤播放 |
| 看出切段 | 波形上段落兩色交錯 |
| 看出說話 | 波形以最大峰值撐滿 |
| 長檔案 | Rust 以 ffmpeg 算波形 |
| 本機檔案 | 只開放專案目錄 |
| 播不了的格式 | 仍顯示波形 |

校對多半點一句聽下去、要改再暫停，所以空白鍵預設接著播，重聽一句時才開單句播放；播放狀態見 10.9。波形在 webview 解碼整段音訊會佔大量記憶體，交給 Rust 以內建的 ffmpeg 計算。拖動改時間見 10.2。

### 10.2 拖動改時間

| 需要 | 做法 |
|---|---|
| 不誤拖 | 只有目前段落可拖 |
| 改一邊 | 拖邊界 |
| 整段移動 | 拖本體，長度不變 |
| 有人插話 | 可拖過鄰段，見 10.12 |
| 對齊 | 8px 內吸附邊界與播放位置 |
| 吸附 | 按住 Shift，或開啟開關 |
| 共用邊界 | 按住 Alt 一起移動 |
| 反悔 | Esc 還原 |
| 新增段落 | 空白處拖出，Enter 建立 |
| 用鍵盤 | F11（macOS 是 F9）、F12 設為播放位置 |
| 確認時間 | 指標時間、起訖與長度 |
| 轉錄或翻譯中 | 不能拖 |

操作沿用 Aegisub 與 Subtitle Edit，放開才寫入，一次拖動是一步復原。吸附同 Aegisub 預設關閉，Shift 反轉開關。開始時間不越過鄰段的開始，段落順序不變。拖動時顯示吸附後的起訖與長度。macOS 的 F11 是顯示桌面，所以和 Subtitle Edit 一樣改用 F9 設開始。

### 10.3 編輯

| 可以改 | 做法 |
|---|---|
| 原文與譯文 | 直接在欄位改，Esc 放棄 |
| 整份的文字 | 搜尋與取代，見 10.10 |
| 簡體字 | 清理，見 10.14 |
| 說話者 | 選單或一次設定 |
| 時間戳 | Aegisub 式覆寫、平移 |
| 段落 | 新增、刪除、合併、切割 |

whisper 的切段常需手動修正，調整時間戳與段落是校對重點。譯文依時間對上原文，所以這些改動一律寫回原文與每種譯文。說話者以原文為準，同步只改標籤，對不上的譯文不刪；選單列出用過與詞彙表的名稱。拖動改時間見 10.2。

### 10.4 對照

| 對照 | 做法 |
|---|---|
| 備份 | 原文與譯文各一份 |
| 其他譯文 | 可複選，唯讀 |
| 版面 | 一律上下疊 |

校對時要同時看原文改了什麼、譯文跟著改了什麼，也常參考其他語言的譯法。備份的差異標在各自的欄位，其他譯文疊在每段下方。上下疊在窄螢幕也放得下，分欄是之後的選項。

### 10.5 匯出

| 選項 | 內容 | 沒有譯文時 | 預設檔名 |
|---|---|---|---|
| 雙語 SRT | 依 1.3 的格式 | 停用 | `ep01.zh-TW.en.srt`；譯文在上時 `ep01.en.zh-TW.srt` |
| 另存原文 | 原文與說話者 | 可用 | `ep01.srt` |
| 另存譯文 | 目前譯文與說話者 | 停用 | `ep01.en.srt` |
| 雙語純文字 | 同雙語 SRT，無時間 | 停用 | `ep01.zh-TW.en.txt` |
| 原文純文字 | 同另存原文，無時間 | 可用 | `ep01.txt` |
| 譯文純文字 | 同另存譯文，無時間 | 停用 | `ep01.en.txt` |

原文與譯文已經自動寫回專案目錄（2.4），匯出只負責目錄裡沒有的雙語 SRT，以及存到其他地方。對話方塊預設開在專案目錄，檔名是資源名稱加上語言代碼。

#### 10.5.1 純文字

```
  阿福: 少爺，晚餐準備好了。
  Alfred: Master, dinner is ready.
                                   ← 段與段之間空一行
  蝙蝠俠: 我等等就下去。
```

純文字給人閱讀，不給播放器，所以去掉時間，一段一塊、塊間空行。內容與說話者寫法和同選項的 SRT 相同，說話者可在匯出選單取消，選擇記在這台電腦。

### 10.6 編輯欄位

| 需要 | 做法 |
|---|---|
| 只收純文字 | `contenteditable="plaintext-only"`，字幕沒有格式 |
| 標記不寫進內容 | CSS Custom Highlight 著色，欄位值仍是原文 |
| 游標在失焦後可見 | 自己畫 Cursor，隱藏原生游標 |
| 不支援 Highlight | 只顯示備份的文字，不標在欄位裡 |
| 與 Stimulus 搭配 | 由 controller 接上 |
| 打錯想重來 | Esc 換回進入時的文字 |

textarea 不能在文字裡標記，後續的詞彙標記與選取都需要。ProseMirror、CodeMirror 為文件或程式碼設計，與逐段的字幕差太多，所以從原生元素做起。欄位本身是不綁定框架的模組。Esc 不寫入也不留復原，沿用清單裡直接編輯的慣例。

### 10.7 Cursor

```
  CURRENT(i) --進入原文或譯文--> LIVE --離開--> KEPT
      ^  ^                        |  ^           |
      |  +-------Esc 放棄---------+  +-再次進入--+
      +------ 其他段成為目前段落、文字被換掉、欄位被鎖住
```

| 狀態 | 畫面 |
|---|---|
| 沒有 Cursor | 只有目前段落的底色 |
| LIVE | 閃爍的游標、選取底色 |
| KEPT | 靜止的游標、選取底色 |
| 選取一段文字 | 只標範圍，不畫游標 |

原生游標只在欄位有焦點時出現，選單與之後的浮動選單卻在焦點移走後才作用在 Cursor 上。所以一律自己畫，有沒有焦點看起來都一樣，不會兩套並存。

### 10.8 目前段落隨改動移動

| 情況 | 目前段落 | Cursor |
|---|---|---|
| 焦點進入列內 | 該段 | 只在原文或譯文 |
| 欄位內 Esc | 不變 | 不保留 |
| 點其他段或時間軸 | 那一段 | 不保留 |
| Shift＋點其他段 | 不變 | 不變 |
| 分割 | 後半段 | 後半段開頭 |
| 從選單或時間軸新增 | 新的段落 | 在它的原文 |
| 刪除目前段落 | 後面留下的段，沒有就往前 | 不保留 |
| 合併含目前段落 | 合併後的段落 | 不保留 |
| 改動其他段落 | 原本那一句 | 不變 |
| 外部改動，段數不變 | 保留 | 文字被換掉就不保留 |
| 外部改動，段數改變 | 無 | 無 |
| 換資源 | 無 | 無 |

盡量維持使用者所在的位置。外部改動指復原、重做、還原與轉錄，它們不說明增減了哪些段落，段數一變就清空。這些規則先依設想訂下，再看使用回饋調整。

### 10.9 播放

```
  暫停 ──播放鈕──> 整段播放 ──播放鈕或空白鍵──> 暫停
  暫停 ──空白鍵──> 整段播放
  暫停 ──空白鍵，開啟單句播放──> 播目前段落 ──播到結尾──> 暫停
  播放中 ──開啟單句播放──> 播到目前段落結尾 ──> 暫停
  播目前段落 ──關掉單句播放──> 整段播放
  暫停 ──選其他段──> 移到那一段，仍暫停
  整段播放 ──點其他列──> 暫停在那一段開頭
  整段播放 ──說話者、Enter、區段──> 繼續播放
  播目前段落 ──選其他段──> 從那一段開頭播
  任何狀態 ──點波形空白處──> 狀態不變，跳到該時間
```

| 操作 | 媒體 |
|---|---|
| 點或聚焦其他段的列 | 暫停在它的開頭 |
| 開其他段說話者選單 | 原處繼續播放 |
| 欄位內 Enter 換段 | 原處繼續播放 |
| 點其他段的區段 | 從點的位置播放 |
| 單句播放時選其他段 | 從它的開頭播 |
| 點目前段落 | 繼續播放 |
| 分割、新增、刪除、合併 | 繼續播放 |
| 播放中開關單句播放 | 立即生效 |
| 改目前段落的結尾 | 停在新的結尾 |

點其他列表示接下來要聽它，所以暫停在開頭，按空白鍵就播下去。標說話者、按 Enter 換段與點區段是邊聽邊改，不打斷播放；區段從點的位置播，與點波形一致。單句播放只播選取的那段，換段就從開頭播。

#### 10.9.1 音量

```
  滑桿位置 p（0–100）─▶ 音量 (p/50)³：中間 1×、最右 8×
  音量 ≤ 100% ─▶ <video>.volume ─────────────────────────────▶ 喇叭
  音量 > 100% ─▶ Web Audio：來源 ─▶ 增益 ─▶ 限幅 ─▶ 抵銷補償 ─▶ 喇叭
                 └ 接上後拔不掉，直到重新啟動
```

| 項目 | 做法 |
|---|---|
| 曲線 | 立方，同 Aegisub |
| 上限 | 800% |
| 限幅 | −1 dBFS、比例 20 |
| 自動補償 | 以固定增益抵銷 |
| 媒體讀取 | 一律用 CORS |

媒體元素最大只到 100%，更大聲只能經過 Web Audio。立方曲線讓滑桿各段的聽感變化相近，上限與 Aegisub 同為 8 倍。Aegisub 只截斷樣本，這裡改用限幅器，放大後大聲處也不失真。限幅器固定會補償增益，所以後面接反向增益抵銷。

#### 10.9.2 延遲

| 來源 | 大小 |
|---|---|
| Web Audio 輸出 | 依裝置，不補償 |
| 限幅器預讀 | 6 ms |

Chromium 把 Web Audio 的延遲當成 0，聲音會晚於畫面。使用者回報聽不出延遲，所以不再做成實驗，只在超過 100% 時接上。若日後有人回報，可讀 `outputLatency` 補償疊字與標時間。

### 10.10 搜尋與取代

| 需要 | 做法 |
|---|---|
| 找出位置 | 搜尋列逐一跳到 |
| 統一標點 | 整份原文或譯文一次取代 |
| 會用正規表示式 | 可選，由 Rust 解讀 |
| 取代錯了 | 一步復原 |
| 沒有符合 | 不寫入，不留復原 |

轉錄的標點常要整份調整，例如把逗號換成空格。比對與取代都在 Rust 以 `regex` crate 執行：資料在 Rust，也不必處理 JS 與 Rust 正規表示式的差異，代價是不支援 lookaround 與反向參照。

### 10.11 跟上播放位置

| 跟著播放位置 | 更新時機 |
|---|---|
| 疊字、時間、播放中的列 | 播放時每一格畫面 |
| 波形游標、單句結尾 | 播放時每一格畫面 |
| 暫停時跳轉 | 播放器回報時間 |

播放器每秒只回報幾次時間，疊字會比聲音晚到四分之一秒，所以播放時每一格畫面都讀一次播放位置。暫停時畫面不動，跳轉仍等播放器回報。單句結尾也每一格重算，播放中開關單句播放或改時間都立即生效。

### 10.12 重疊段落

```
  疊字     對啊          後開始的在上方
           大家好
  時間軸   上軌      [對啊]
           下軌  [─── 大家好 ───]    沒重疊的佔滿高度
```

| 需要 | 做法 |
|---|---|
| 有人插話 | 段落可重疊 |
| 看見插話 | 疊字疊在上方 |
| 點得到每段 | 重疊的區段分軌 |
| 蓋在段落上新增 | 按住 Ctrl 或 ⌘ 拖出 |
| 不打亂順序 | 開始不越過鄰段的開始 |
| 兩人同時說 | 同起訖依順序對譯文 |

插話會蓋過正在說的句子，所以段落可以重疊，疊字與時間軸都由下往上疊，和播放器疊字幕的方式一致。譯文依起訖對上原文，起訖相同的依檔案裡的順序配對。段落維持開始時間的順序，編號與目前段落才不會跳動。

### 10.13 影片視窗

```
  主視窗的 JS ──window.open──> 同源的影片視窗
       │                          │
       └─ 把同一個 <video> 移過去 ─┘  時間只有一個，聲音在同一個播放器
```

| 需要 | 做法 |
|---|---|
| 大畫面看細節 | 影片移到獨立視窗 |
| 編輯區不被擠壓 | 控制與時間軸留在主視窗 |
| 多出編輯空間 | 上排只留控制列 |
| 聲音畫面不錯開 | 移動播放器，不複製 |
| 三個平台都能用 | 用 webview 的新視窗 |
| 關掉視窗 | 影片回到預覽 |
| 放在固定的螢幕 | 記住位置與大小 |

兩個播放器各自解碼會錯開幾十毫秒，使用者連 0.1 秒都察覺得到，所以影片視窗與主視窗共用一份 JS，把同一個播放器移過去。子母畫面與 WebRTC 在部分 webview 不能用，所以不採用。

### 10.14 清理簡體

```
  文字 ─▶ STPhrases 片語 ─▶ STCharacters 單字 ─▶ TWVariants 台灣異體 ─▶ 繁體
          （定讀音）         （本身也是繁體的字不轉）
```

| 需要 | 做法 |
|---|---|
| 清掉模型的簡體 | 內建 OpenCC 字典 |
| 繁體不被改動 | 也列自己的字不單獨轉 |
| 台灣寫法 | 台不改成臺 |
| 不改說法 | 不收 TWPhrases |
| 離線 | 字典編譯進執行檔 |

字典照原樣放在 `src-tauri/opencc/`，由 Rust 比對，不需要安裝 OpenCC。后、里這類本身也是繁體的字只在片語裡轉，猜錯比留著更糟。只轉寫法、不換用詞，說過的話不會被改掉。

快速鍵越來越多，記不住的人需要一處查詢。同一個鍵在欄位內外作用不同，所以一覽依何時有效分組，tooltip 說明條件。配置見 `docs/ui.md` 1.4。

```
                   │   確認能回應版本參數
                   ▼
              寫入授權頁 ─▶ 打包並簽章 ─▶ 檢查簽章 ─▶ 上傳產物
```

| 觸發 | 新的 push 進來時 | 原因 |
|---|---|---|
| PR | 取消舊的一輪 | 只有最新的有用 |
| stable | 各自跑完 | 釋出的 commit 要打包 |
| main 檢查 | 各自跑完 | 每個 commit 有結論 |
| main 打包 | 跑的做完，只留最新的排隊 | 只發布最新的預覽版 |

預覽版只保留最新一版，所以排隊中較舊的打包直接放棄；正在打包的不中斷，連續 push 時仍會產出。

action 釘 commit SHA，下載的工具釘 SHA256。Rust cache 以編譯器版本與 lockfile 為 key，存檔前移除會重新編譯的產物。元件 cache 以平台、變體、該元件的釘版與建置腳本為 key，只重編改到的元件；cache 過期時由 GitHub 清除，下次打包重新編譯。

### 13.2 產物與授權頁

| 平台 | 打包產物 | 附到 Release |
|---|---|---|
| Windows | exe、NSIS、MSI | NSIS、MSI |
| macOS | dmg、`.app` | dmg、`.app.tar.gz` |
| Linux | deb、rpm | deb、rpm；預覽版只 deb |

授權頁依該平台的內建變體寫成，隨介面打包，不另附檔案（4.4）。Linux 只出 deb、rpm，GTK 等函式庫取自系統，不必再附它們的授權；元件需要的 libgomp、libvulkan 也寫進套件相依。更新用的套件各附簽章 `.sig`，見 13.5。

### 13.3 釋出流程

```
  main（trunk）─PR 合併─▶ stable ─▶ release-please
                                     ├ 一般 commit ─▶ 更新版本 PR
                                     └ 合併版本 PR ─▶ 建立 tag 與草稿 Release
  CI 成功 ─▶ release-assets（也可指定 tag 或 preview 手動觸發）
               ├ stable：commit 是 tag 指向的嗎？是 ─▶ 附檔 ─▶ 公開 Release
               └ main：新建 v<預覽版號> tag 與 Prerelease ─▶ 附檔 ─▶ 只留最新 5 版
               附檔：安裝檔、簽章、latest.json、ffmpeg 原始程式碼、SHA256SUMS
  release-assets 完成 ─▶ pages（13.5.4）
```

日常 commit 在 main，驗證後以 PR 合併進 stable 才發正式版；stable 只收 PR，只用 merge commit，保留每個 commit 給 changelog。版號與 changelog 由 release-please 管理，直接取用 CI 的打包，不重新編譯；Release 附完檔才公開。預覽版的 Release 標題與設定頁同樣稱呼：以哪個正式版為基礎、建置時間（UTC），說明列出完整版號與 commit，回報時對得上。預覽版每版一個 tag，只建立不移動：workflow 的 token 不能把 tag 移到 workflow 檔案不同的 commit；舊版連同 tag 刪除，只留最新 5 版。不做程式碼簽章，放行步驟寫在 README。

### 13.4 失敗時補救

| 情況 | 補救 |
|---|---|
| 附檔失敗 | 重跑 release-assets |
| CI 失敗或被取消 | 重跑 CI，完成後自動附檔 |
| CI 產物已過期 | 對 tag 手動跑 CI 再附檔 |
| 預覽版附檔失敗 | 以 preview 手動重跑 |
| 網站部署失敗 | 手動重跑 pages |

附檔一律覆寫同名檔案，重跑就是補檔；正式版失敗時停在草稿。release-assets 與 pages 由 `workflow_run` 觸發，GitHub 只採用預設分支 main 上的版本，所以正式版也用主線上的版本附檔。

### 13.5 自動更新

| 事項 | 設計 |
|---|---|
| 機制 | Tauri updater plugin |
| 更新來源 | 更新網站的通道清單 |
| 簽章 | Tauri 金鑰，綁定版號 |
| 檢查 | 啟動時與手動 |
| 安裝 | 使用者按下才開始 |

私鑰放在 CI secret。updater 用自己的金鑰簽章，跟作業系統要求的程式碼簽章無關，所以不做程式碼簽章也能自動更新。

#### 13.5.1 簽章與清單

```
  CI 打包（疊加 tauri.updater.conf.json）─▶ 每個更新套件的 .sig
    └ scripts/signatures.ts：公鑰與版號都對才通過
  release-assets ─▶ scripts/manifest.ts ─▶ latest.json
    ├ 正式版：簽章版號須等於 tag
    └ 預覽版：先改固定檔名，版號取自簽章，不含 rpm
```

| key | 套件 |
|---|---|
| `darwin-aarch64-app` | `.app.tar.gz` |
| `windows-x86_64-nsis` | `-setup.exe` |
| `windows-x86_64-msi` | `.msi` |
| `linux-x86_64-deb` | `.deb` |
| `linux-x86_64-rpm` | `.rpm` |

簽章綁定版號（`requireSignedVersion`），清單不能把新版號配上舊套件。每種格式各有 key，不會拿到別種安裝檔。預覽版號的 `+<run>` 會被 GitHub 改寫，所以 tag 與檔名去掉它，如 `v0.1.1-preview.202609281430`、`Tsuzuri_0.1.1-preview.202609281430_x64-setup.exe`；完整版號仍寫在清單與 Release 說明。開發機打包不需要金鑰。

#### 13.5.2 安裝

```
  更新 ─▶ Mode 執行中？─是─▶ 拒絕
           │否，取得 Mode 的執行權
           ▼
         下載、驗簽 ─▶ 停止所有元件 ─▶ 安裝 ─▶ 重新啟動
```

| 規則 | 原因 |
|---|---|
| 執行中拒絕 | 安裝會停止元件 |
| 安裝前停元件 | 安裝檔無法覆寫執行中的檔案 |
| 持有執行權 | 安裝時不會開始新任務 |
| 啟動檢查失敗不通知 | 使用者沒有要求 |

Windows 的安裝程式啟動後直接結束 Tsuzuri，不經過結束時的 `kill_all`，所以停元件放在安裝之前。下載進度每 1% 回報一次，避免大檔案的事件塞滿介面。

#### 13.5.3 更新通道

```
  最新正式 tag v0.2.0 ─▶ 預覽版號 0.2.1-preview.<UTC 時間>+<run>
    0.2.0  <  0.2.1-preview.…  <  0.2.1（下一個正式版）
  選穩定版 ─▶ updates/stable.json    選預覽版 ─▶ updates/preview.json
  預覽版切回穩定版 ─▶ 等下一個正式版，或按「立即退回」
```

| 規則 | 原因 |
|---|---|
| 版號不 commit | 合併進 stable 不衝突 |
| `+<run>` | MSI 只收數字 |
| 立即退回只此一次 | 其他檢查仍防降版 |
| rpm 只有穩定版 | rpm 把預覽排在後面 |
| 未選通道跟著版本 | 測試者持續收到預覽 |

預覽版號在打包前寫入 Cargo.toml，顯示時改說以哪個正式版為基礎與建置時間（`docs/ui.md` 7.1.1）。rpm 會把預覽版排在後續正式版之後，裝了就離不開，所以預覽版不出 rpm。

#### 13.5.4 更新網站

```
  release-assets 完成、site/ 改動 ─▶ pages
    ├ 取最新正式版與最新 Prerelease 的 latest.json
    ├ updates/preview.json 取兩份中版號較新者
    └ 連同 site/ 整站部署到 tsuzuri.aotoki.me
```

| 事項 | 做法 |
|---|---|
| 原始資料 | Release 的附檔 |
| 安裝檔 | 仍放 Release |
| 網址 | 自有網域 |
| 需要的設定 | Pages、網域、DNS |

App 內寫死的網址指向自有網域，安裝檔之後搬家也不必更新 App。網站只複製 Release 上的清單，重跑就能重建。Pages 需在設定啟用 Actions 來源與自訂網域，DNS 加上指向 GitHub 的 CNAME。

## 14 風險與待驗證

| 小節 | 範圍 |
|---|---|
| 14.1 平台 | 系統、驅動與打包 |
| 14.2 安全與行程 | 防護與行程紀錄 |
| 14.3 功能 | 字幕格式與模組 |

這些風險不阻擋目前的開發，但正式釋出前要逐一處理或接受。

### 14.1 平台

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| Windows 無自動測試 | 行程清理可能失效 | 實機已確認；補測試 |
| 變體實際速度 | 自動選擇順序要調 | 不同硬體量 RTF |
| 沒有 Vulkan 驅動程式 | 內建元件無法執行 | 改指定 CPU 版 |
| macOS 未經公證 | 首次開啟被擋 | 確認可強制打開 |
| 自動更新未實測 | 某平台無法更新 | 下一版釋出時實測 |
| 預覽版升級未實測 | MSI、deb 更新失敗 | 第一次預覽版實測 |

變體指 Vulkan 與 OpenBLAS。沒有驅動程式時先顯示無法執行，自動選擇上線後改為自動退回。macOS 產物以 `signingIdentity: "-"` 完整 ad-hoc 簽章，應能從隱私權設定強制打開；下載後實際確認前，README 仍保留 `xattr` 移除隔離的做法。

### 14.2 安全與行程

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| CSP 關閉 | 少一層防護 | 設 CSP 後確認介面 |
| 殘留行程只比名稱 | PID 重用時誤殺 | 評估比對啟動時間 |
| updater 私鑰遺失 | 無法再自動更新 | CI 以外另存備份 |

殘留行程以執行檔名稱比對，PID 被系統重用時可能誤殺同名行程。私鑰只存在 CI 時，一旦遺失，已安裝的版本就無法再自動更新。

### 14.3 功能

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| 說話者取到第一個冒號 | 一般句子被當說話者 | 收集實際字幕 |
| 辨識工具未定 | VRAM 或授權不合 | 依 8.2 評估 |

Netflix 繁中指南的 `我問：「…」`、`日期：…`、`導演：…` 也會被當成說話者，寫出時冒號統一為 `: `。長度限制擋不住這些短句，故不採用。辨識工具可能超出 4GB VRAM，或授權不允許散布。
