# Tsuzuri 設計

Tsuzuri（綴り）在本機把影片與音訊轉成字幕，並提供翻譯與校對，音訊與文字不離開使用者的電腦。它為有隱私需求、不能上傳雲端的情境而生。這份文件記錄設計的意圖與取捨，行為與介面的細節以 `.spec/` 為準。

## 0 總覽

### 0.1 設計承諾

| 承諾 | 意義 |
|---|---|
| 本機處理 | 音訊與文字不離開電腦；網路只用於首次設定、更新與使用者主動下載 |
| 元件內建且可覆寫 | 安裝檔內建能在各平台執行的元件；使用者指定的版本永遠優先 |
| 一次只載入一個模型 | 各 Step 依序執行，前一個行程結束才開始下一個，4GB VRAM 也能用 |
| 不留下行程 | 不論正常結束或當掉，都不讓元件行程繼續佔用記憶體或 port |
| 流程由使用者組合 | 轉錄與翻譯是模組，三種模式只是預設的組合 |

這五項是設計的固定點。兩項衝突時，由該章說明哪一項讓步。

### 0.2 系統分層

```
  ┌───────────────────────────────┐
  │ Webview：Stimulus controller  │  畫面與互動，不保存工作狀態
  └───────────────┬───────────────┘
                  │ Tauri command、事件
  ┌───────────────▼───────────────┐
  │ 工作流程：模組與 Step          │  決定哪些模組、以什麼順序執行
  └───────────────┬───────────────┘
                  │ Processes::spawn
  ┌───────────────▼───────────────┐
  │ 行程                          │  啟動、記錄、清理子行程
  └───────────────┬───────────────┘
                  │ 絕對路徑
  ┌───────────────▼───────────────┐
  │ 元件：ffmpeg、whisper-cli、    │  外部執行檔，載入使用者的模型
  │       llama-server            │
  └───────────────────────────────┘
```

每層只與相鄰的層溝通。所有運算都在元件行程裡，GPU 或記憶體出問題只會結束該行程，介面不受影響。

## 1 字幕資料

所有模組都讀寫同一種資料，沒有相依。

### 1.1 Segment 與 Transcript

| 概念 | 內容 |
|---|---|
| Segment | 一段語音：開始時間、結束時間、說話者（可省略）、文字；翻譯後另有譯文 |
| Transcript | 一個媒體檔的所有 Segment，依時間排序 |

模組之間只交換 Transcript，不交換各元件自己的輸出格式。這讓轉錄可以換引擎、翻譯可以接既有字幕，而不影響其他模組。

### 1.2 SRT 讀寫

| 情況 | 處理 |
|---|---|
| BOM | 讀入時清除，寫出一律不帶；部分播放器遇到 BOM 會顯示亂碼 |
| CRLF | 讀入時與 LF 相同 |
| 說話者 | 文字開頭的 `標籤:`，例如 `co:`、`cl:` |
| 一段文字有多行 | 保留換行 |
| 時間格式錯誤 | 失敗，並指出是第幾段 |
| 編輯後的文字含空行 | 寫出時移除空行，避免一段被切成兩段 |

SRT 是 Transcript 在磁碟上的唯一格式：whisper-cli 輸出它、使用者提供它、儲存也用它。

## 2 行程

元件以子行程執行，沒有相依。

### 2.1 啟動與紀錄

```
  Processes::spawn(絕對路徑)
    ├ 記錄 PID 與執行檔名稱到 app data
    ├ 轉送 stdout、stderr 事件給呼叫端
    └ 行程結束 → 從紀錄移除
```

一律以絕對路徑啟動，不用 Tauri 的 sidecar，因為元件不一定來自安裝檔。元件由 App 直接啟動，不再開子行程，所以紀錄涵蓋全部行程。

### 2.2 清理

| 情境 | 機制 |
|---|---|
| App 正常結束 | 在 `RunEvent::Exit` kill 仍在執行的子行程 |
| App 當掉或被強制結束 | 下次啟動時，kill 紀錄中還活著且名稱相符的行程（Windows 用 `taskkill /T /F`） |
| PID 已被其他程式重用 | 名稱不符就不動它 |

`tauri-plugin-shell` 只清理從 JS 端啟動的行程，所以 App 自己負責 Rust 端啟動的行程。當掉後的殘留會佔著 VRAM 直到下次啟動。

## 3 元件

相依：第 2 章，元件以行程執行。

### 3.1 尋找順序

```
  使用者指定的執行檔（例如 CUDA 版）
        │ 沒有，或檔案不在
        ▼
  偵測已安裝的版本（PATH、Homebrew、Nix；要能回應版本參數）
        │ 找不到
        ▼
  安裝檔內建的變體（依 0.4 自動選擇）
        │ 沒有
        ▼
  提示怎麼安裝
```

使用者指定的永遠優先，這是 CUDA 等進階設定的入口。macOS 的 App 讀不到 shell 的 PATH，所以常見的安裝目錄逐一列出。

### 3.2 內建變體

| 元件 | 變體 | 理由 |
|---|---|---|
| whisper.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 上游會刪除舊的 nightly，不能釘上游的執行檔 |
| llama.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 與 whisper.cpp 一致 |
| ffmpeg | 純音訊的 LGPL 版 | 只需要解出音軌，範圍小、授權單純 |

自動選能執行的最快變體。選擇結果顯示在首次設定引導與設定頁，可以手動改。

### 3.3 自行編譯

| 平台 | 編譯環境 |
|---|---|
| Windows | GitHub Actions 的 Windows runner 原生編譯 |
| Linux | GitHub Actions 的 Linux runner |
| macOS | GitHub Actions 的 macOS runner |

原始程式碼的版本與 SHA256 釘在 `scripts/vendor.sh`，CI 與開發機跑同一支腳本。開發時的 debug build 會先偵測 `vendor/`，release build 不引用它。

### 3.4 授權

| 元件 | 授權 | 我們的義務 |
|---|---|---|
| whisper.cpp、llama.cpp | MIT | 附上授權聲明 |
| ffmpeg | LGPL 2.1+ | 不開 GPL、nonfree；隨版本附上對應的原始程式碼；標示 FFmpeg 授權 |
| Rust 相依套件 | 見 `deny.toml` | cargo-deny 檢查、cargo-about 產生授權聲明 |

ffmpeg 是獨立執行檔，Tsuzuri 不連結它的函式庫，使用者也能改用自己的 ffmpeg。純音訊版不含視訊解碼器。

## 4 模型

模型由使用者提供，沒有相依。

### 4.1 指定與檢查

| 用途 | 已驗證的模型 | 規則 |
|---|---|---|
| 轉錄 | Breeze-ASR-25（中文） | 指定本機檔案並記住；啟動引擎前檢查檔案還在 |
| 翻譯 | Qwen3-4B-Instruct-2507 | 同上；0.8B 等級品質不足 |

App 不下載模型，也不把模型寫進元件清單。檔案被移走時提示重新指定，不啟動引擎。

## 5 工作流程

相依：第 1～4 章，流程串起的模組需要字幕資料、行程、元件與模型。

### 5.1 模組與流程

```
  媒體檔 ──▶ [轉錄模組] ──▶ Transcript ──▶ [翻譯模組] ──▶ Transcript（含譯文）
                                ▲
  SRT 檔 ───────────────────────┘
```

模組以 Transcript 為輸入或輸出，使用者可以組合它們。流程依序執行，前一個模組的行程全部結束後，下一個才開始。

### 5.2 預設流程

| 流程 | 組成 |
|---|---|
| 轉錄 | 轉錄模組 |
| 翻譯 | 讀入 SRT → 翻譯模組 |
| 轉錄後翻譯 | 轉錄模組 → 翻譯模組 |

目前三種模式寫死在程式裡。改成可組合後，它們變成內建的範本，使用者可以另外建立自己的流程。

### 5.3 進度與取消

| 規則 | 說明 |
|---|---|
| 每個模組回報進度 | 名稱、百分比，能算就附「第 N / 共 M」 |
| 算不出進度時 | 顯示不定進度，例如載入模型 |
| 取消 | 結束目前的行程，已完成的 Transcript 保留 |

目前轉檔與載入模型一直停在 0%，轉錄每 30 秒才更新一次。各模組的改善寫在第 6、7 章。

## 6 轉錄模組

相依：第 5 章，以模組身分加入流程。

### 6.1 Step

```
  媒體檔 ─▶ ffmpeg ─▶ 16kHz 單聲道 WAV ─▶ whisper-cli ─▶ SRT ─▶ Transcript
```

先轉成統一格式，轉檔失敗與轉錄失敗可以分開診斷。兩個 Step 依序執行，whisper-cli 結束即釋放記憶體。

### 6.2 語言

| 設定 | 設計 |
|---|---|
| 轉錄語言 | 使用者選擇，傳給 whisper-cli 的 `-l` |
| 模型建議 | 依語言建議模型；Breeze-ASR-25 只適合中文 |

目前固定為中文（`-l zh`），其他語言的音檔會被當成中文辨識。語言清單與模型建議尚未決定。

### 6.3 進度

| Step | 進度來源 |
|---|---|
| 轉檔 | ffmpeg `-progress` 回報已處理時間，除以總長度 |
| 轉錄 | whisper-cli 逐段印出結束時間，除以總長度 |

逐段印出的內容也能即時顯示在畫面上。完成時回報音檔長度與轉錄耗時，用來計算 RTF。

## 7 翻譯模組

相依：第 5 章，以模組身分加入流程。機制參考翻譯 PoC（qwen-translator-script），它針對小模型常見的漏翻、重複、跨句錯位設計了分層的修復。

### 7.1 llama-server 生命週期

```
  隨機 port 啟動 ─▶ 輪詢 /health 直到就緒 ─▶ 送出各批翻譯 ─▶ 停止行程
```

每次工作啟動一個 llama-server，結束或放棄時停止。context 預設 4096，使用者可依硬體在設定調整；不沿用模型自帶的超長 context，避免撐爆 VRAM。

### 7.2 分批

| 規則 | 說明 |
|---|---|
| 每批數句 | PoC 預設 8 句，比逐句翻譯少很多請求 |
| 同一句不拆開 | 被切成多段的一句話排在同一批 |
| 失敗就拆半 | 重試多次仍失敗時，把該批拆成兩半再試 |
| 說話者標籤 | 只送對話本體，譯完原樣接回標籤 |

目前逐段翻譯，模型看不到前後文，長字幕要發幾百個請求。

### 7.3 翻譯詞彙表

| 設定 | 設計 |
|---|---|
| 格式 | 每一列是原文與譯文，例如人名、片名 |
| 帶入方式 | 每批只帶入有出現在該批原文裡的詞 |
| 檢查 | 譯文沒照詞彙表時視為翻壞，觸發重試 |

小模型對陌生的專有名詞容易猜錯。翻譯詞彙表由使用者提供，跟 `.spec/glossary.md` 無關。

### 7.4 滾動摘要

| 設定 | 設計 |
|---|---|
| 內容 | 不超過指定字數的前文摘要，每翻完一批更新一次 |
| 代價 | 每批多一次請求；PoC 實測總時間約多 30% |
| 限制 | 沒搭配翻譯詞彙表時，模型會把摘要裡的人名錯套到其他人 |

補足分批只看得到附近幾句的限制。因為有錯套人名的風險，只在有翻譯詞彙表時建議開啟。

### 7.5 自我修復

| 偵測到 | 處理 |
|---|---|
| 重複、漏翻、殘留原文 | 重試；仍失敗就保留原文 |
| 違反翻譯詞彙表、疑似吃掉否定詞 | 重試；仍失敗就保留目前最好的版本 |

確定翻壞就不留下；問題輕微時，寧可保留不完美的譯文。否定詞檢查在 PoC 只支援翻成英文。

## 8 字幕校對與儲存

相依：第 1、5 章，校對的對象是流程產出的 Transcript。

### 8.1 預覽與時間軸

```
  ┌──────────────────────┐  ┌──────────────────────┐
  │ 影片預覽              │  │ 段落清單              │
  │   目前時間 00:01:02   │◀─┤ ▶ 00:01:00 co: ……    │  點段落跳到該時間
  │   字幕疊在畫面上      │──▶│   00:01:04 cl: ……    │  播放時標出目前段落
  └──────────────────────┘  └──────────────────────┘
```

校對要邊看影片邊改字幕。放入影片後，預覽與段落清單的時間軸同步，並能直接拖動段落的開始與結束時間。

### 8.2 編輯

| 可以改 | 狀態 |
|---|---|
| 原文與譯文 | 已有 |
| 說話者 | 尚缺；從選單挑選或新增標籤 |
| 時間戳 | 尚缺；搭配 8.1 的預覽調整 |
| 合併、切割段落 | 尚缺 |

whisper 的切段常常需要手動修正，所以調整時間戳與段落是校對的重點。

### 8.3 儲存

| 方式 | 做法 | 階段 |
|---|---|---|
| A. 未存檔提醒 | 關閉或載入新檔前提醒 | 初期 |
| B. 寫到原檔旁 | 完成時自動寫出 `影片名.srt` 與譯文的 SRT | 初期 |
| C. 暫存最近一次 | 重開 App 可以接著編 | 之後 |
| D. 工作清單 | 每個媒體檔一筆，可隨時回來繼續 | 之後 |

目前結果只存在畫面上，關掉或載入新檔就會消失。四種方式最終都需要，初期先做 A 與 B。

## 10 建置與釋出

相依：全部章節，打包的是前面各章的成果。

### 10.1 CI

```
  push、PR ─▶ spec（sumi）
           ├▶ licenses（cargo-deny、cargo-about）
           ├▶ frontend（Vitest、型別檢查）
           └▶ rust × 3 平台（fmt、clippy、test）
                   │ 全部通過，且是 push main 或手動觸發
                   ▼
              build × 3 平台 ─▶ 上傳產物
```

action 釘 commit SHA，下載的工具釘 SHA256。Rust cache 以編譯器版本與 lockfile 為 key，存檔前移除會重新編譯的產物。

### 10.2 產物與授權聲明

| 平台 | 產物 |
|---|---|
| Windows | `tsuzuri.exe`、NSIS 安裝檔、MSI |
| macOS | dmg、`.app` |
| Linux | 各種安裝包 |
| 全部 | `THIRD-PARTY-LICENSES.html` |

授權聲明目前只涵蓋 Rust 相依，前端打包進 App 的 JS 相依尚缺。

### 10.3 釋出流程

```
  合併到 main ─▶ release-please 更新版本 PR
  合併版本 PR ─▶ 建立 tag 與 GitHub Release
              ─▶ CI 打包並附上產物、ffmpeg 原始程式碼、更新資訊
```

版號與 changelog 由 release-please 管理。不做作業系統的程式碼簽章；macOS 與 Windows 的放行步驟寫在 `README.md` 與 `README.zh-TW.md`。

### 10.4 自動更新

| 事項 | 設計 |
|---|---|
| 機制 | Tauri updater plugin |
| 更新來源 | GitHub Release 附帶的更新資訊檔 |
| 簽章 | updater 強制驗證更新檔；用 Tauri 自己的金鑰，私鑰放在 CI secret |

updater 用自己的金鑰簽章，跟作業系統要求的程式碼簽章無關，所以不做程式碼簽章也能自動更新。

## 11 風險與待驗證

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| Windows 專屬程式碼沒有自動測試 | 殘留行程清理可能失效 | Windows 實機測試；補 Windows 測試 |
| CSP 關閉 | 少一層防護 | 設定 CSP 後確認介面正常 |
| Vulkan、OpenBLAS 變體實際多快 | 自動選擇順序可能要調整 | 在不同硬體上量 RTF |
| Linux 系統函式庫 | 缺 libgomp1、libvulkan1 時跑不起來 | `.deb` 宣告相依 |
| 殘留行程只比對名稱 | PID 重用時可能誤殺同名行程 | 評估是否加上啟動時間比對 |
| macOS 產物只有 linker 產生的 ad-hoc 簽章，且不完整 | 下載後顯示「已損毀」，沒有「強制打開」可選，只能用 `xattr` 移除隔離標記 | 打包時以 `signingIdentity: "-"` 完整 ad-hoc 簽章後，確認出現「強制打開」 |
| updater 私鑰遺失 | 已安裝的版本無法再自動更新 | 在 CI 以外另存私鑰備份 |

這些風險不阻擋目前的開發，但正式釋出前要逐一處理或接受。
