# Tsuzuri 設計

Tsuzuri（綴り）在本機把影片與音訊轉成字幕，並提供翻譯與校對，音訊與文字不離開使用者的電腦。它為有隱私需求、不能上傳雲端的情境而生。這份文件記錄設計的意圖與取捨，行為與介面的細節以 `.spec/` 為準。

## 0 總覽

### 0.1 設計承諾

| 承諾 | 意義 |
|---|---|
| 本機處理 | 音訊與文字不離開電腦 |
| 元件內建且可覆寫 | 使用者指定的優先 |
| 一次只載入一個模型 | 4GB VRAM 也能用 |
| 不留下行程 | 當掉也不佔記憶體或 port |
| 流程由使用者組合 | 模式只是預設組合 |

網路只用於首次設定、更新與使用者主動下載。安裝檔內建能在各平台執行的元件。各 Step 依序執行，前一個模型釋放才載入下一個。轉錄、說話者辨識與翻譯是模組。這五項是設計的固定點，兩項衝突時由該章說明哪一項讓步。

### 0.2 系統分層

| 意圖 | 做法 |
|---|---|
| 單一事實來源 | 資料都在 Rust |
| 介面不被拖慢 | 處理留在 Rust |
| 當掉不影響介面 | 運算在子行程 |

Webview 顯示的資料都向 Rust 查詢，變更也都寫進 Rust，自己只負責畫面、互動與多語系。GPU 或記憶體出問題只結束該元件行程。分層、模組與相依規則見 `docs/architecture.md`。

## 1 字幕資料

所有模組都讀寫同一種資料，沒有相依。

行為：`transcript.md`。

### 1.1 Segment 與 Transcript

| 概念 | 內容 |
|---|---|
| Segment | 一段語音 |
| Transcript | 依時間排的 Segment |
| 譯文 | 一次一種語言 |
| 多語言對照 | 尚不需要 |

Segment 有開始、結束時間、可省略的說話者與文字，翻譯後另有譯文；譯文靠時間對上原文。Transcript 是一個媒體檔的全部 Segment。模組之間只交換 Transcript，不交換各元件自己的輸出格式。這讓轉錄可以換引擎、翻譯可以接既有字幕，而不影響其他模組。

### 1.2 SRT 讀寫

| 情況 | 處理 |
|---|---|
| BOM | 讀入清除，寫出不帶 |
| CRLF | 讀入時與 LF 相同 |
| 說話者 | 第一行開頭的 `標籤:` |
| 一段文字有多行 | 保留換行 |
| 時間格式錯誤 | 失敗，並指出是第幾段 |
| 文字含空行 | 寫出時移除 |

SRT 是 Transcript 交換的唯一格式：whisper-cli 輸出、使用者提供、匯出都用它。有些播放器遇到 BOM 會亂碼，空行會把一段切成兩段。標籤只在其他行都沒有時成為說話者，寫出時加回；譯文用詞彙表裡該語言的名稱（9.3）。讀入譯文只拿掉原文說話者的標籤。

### 1.3 雙語 SRT

```
  1
  00:00:01,000 --> 00:00:03,500
  CO: 今天我們來談隱私               ← 原文（預設在上）
  CO: Today we talk about privacy    ← 譯文
```

| 情況 | 處理 |
|---|---|
| 順序 | 預設原文在上 |
| 說話者 | 各自語言的名稱 |
| 某段沒有譯文 | 只寫出原文 |
| 讀入雙語 SRT | 使用者選擇是否拆開 |

一份字幕同時顯示兩種語言，播放器不需要額外支援。專案設定可改成譯文在上，檔名的語言代碼也依此順序；說話者名稱沒有另外指定時兩行相同。有些字幕本來就會換行，無法判斷是否為雙語，所以讀入時由使用者決定，預設整段當成原文。

## 2 專案

專案對應一個目錄，收納同一系列作品的媒體檔、字幕與設定，例如一部作品的各集。相依：第 1 章。

行為：`project.md`、`versions.md`、`undo.md`。

### 2.1 專案目錄

```
  lecture/                     ← 專案
  ├── tsuzuri.config.json      ← 專案設定（2.3）
  ├── glossary.csv             ← 翻譯詞彙表（9.3）
  ├── .tsuzuri/history/        ← 產出與覆蓋前的備份（2.5），不當成資源
  ├── ep01.mp4  ┐
  ├── ep01.srt  ├ 資源 ep01：媒體檔、主語言字幕、en 譯文
  ├── ep01.en.srt ┘
  ├── ep02.mp4                 ← 資源 ep02：只有媒體檔，可以轉錄
  └── ep03.srt                 ← 資源 ep03：只有字幕，可以編輯與翻譯
```

| 概念 | 內容 |
|---|---|
| 資源 | 同檔名的媒體檔與字幕 |
| 目前資源 | 編輯畫面與任務的對象，一次一個 |

資源是一集或一段錄音。目錄就是事實來源，Tsuzuri 不另外儲存字幕的副本。只有字幕的資源就是單純編輯字幕。

### 2.2 資源配對

| 檔案 | 角色 |
|---|---|
| `[name]` 加上內建 ffmpeg 能讀的副檔名 | 媒體檔：`.mp4`、`.mov`、`.m4a`、`.mkv`、`.webm`、`.mp3`、`.wav`、`.ogg`、`.opus`、`.flac`、`.aac` |
| `[name].srt` | 主語言字幕 |
| `[name].[主語言].srt` | 主語言字幕；與 `[name].srt` 並存時用 `[name].srt` |
| `[name].[lang].srt` | `lang` 譯文，`lang` 是主語言以外的語言 |
| `[name].[lang].[lang].srt` | 雙語匯出，不載入 |
| 不認得的語言代碼 | 不載入 |

譯文依開始與結束時間對上主語言的段落，對不上的段落沒有譯文。同一資源可以有多種譯文，一次編輯一種。

### 2.3 專案設定

| 設定 | 沒有設定檔時 |
|---|---|
| 主語言 | 依介面語言 |
| 翻譯語言 | 未指定；翻譯後記下 |
| 雙語順序 | 原文在上（1.3） |
| 自動儲存雙語 | 關閉 |
| 覆蓋前備份 | 關閉 |

```
  軟體設定（預設值） ─▶ 專案設定（覆寫） ─▶ 任務的選項（只用這一次）
```

專案設定存在 `tsuzuri.config.json`，第一次改動時建立。介面是正體中文時主語言預設 `zh-TW`，其他為 `en`。主語言在設定畫面修改，轉錄與翻譯都以它為原文語言。

### 2.4 寫回

| 時機 | 寫入 |
|---|---|
| 編輯原文 | 主語言字幕 |
| 編輯譯文 | 目前的譯文 |
| 編輯說話者 | 原文與每種譯文 |
| 轉錄完成 | `[name].srt` |
| 翻譯完成 | `[name].[lang].srt` |
| 自動儲存雙語 | `[name].[a].[b].srt` |

自動寫回讓關掉 App 不會遺失結果，字幕也直接能交給播放器。說話者依時間帶到每種譯文，對不上的不動；轉錄寫出後只寫入有改變的譯文。自動儲存雙語開啟時，寫出原文更新每種雙語檔，寫出譯文只更新那一種。

### 2.5 備份與復原

| 情況 | 做法 |
|---|---|
| 任務寫出後 | 留成產出備份 |
| 覆蓋前備份開啟 | 覆蓋前先複製 |
| 還原備份 | 先備份目前的再取代 |
| 每次改動前 | 記下一步，最多 100 |
| 任務進行中 | 鎖住它寫入的字幕 |

備份在 `.tsuzuri/history/`，產出備份檔名是 `[name][.lang].[UTC 時間].output.srt`，覆蓋前備份少了 `.output`；產出備份是之後比較的對象。復原記下這個資源所有字幕的內容，專案開著時可以重做，外部改過就清掉。轉錄鎖住整個資源，翻譯只鎖那份譯文。

### 2.6 開啟與重讀

| 情況 | 做法 |
|---|---|
| 開啟目錄 | 掃描資源，選第一個 |
| 開啟 SRT | 開它的目錄並選取 |
| 切回視窗 | 外部改過就重讀 |
| 寫回前內容不同 | 重讀，不寫入並告知 |

字幕常在專業字幕軟體裡再修，所以寫回前先比對內容，外部的修正不會被自動寫回蓋掉。不比對修改時間，因為有些檔案系統的時間不夠精細，緊接的兩次寫入會一樣。

### 2.7 最近的專案

| 欄位 | 內容 |
|---|---|
| 名稱 | 目錄名稱 |
| 路徑 | 目錄完整路徑 |
| 開啟時間 | 最近一次開啟時間 |

每個目錄一筆，記在軟體設定裡。沒有開啟專案時，這份清單顯示在起始畫面（11.2）。

## 3 行程

元件以子行程執行，沒有相依。

行為：`processes.md`、`observability.md`。

### 3.1 啟動與紀錄

```
  Processes::spawn(絕對路徑)
    ├ 記錄 PID 與執行檔名稱到 app data
    ├ 轉送 stdout、stderr 給呼叫端，並逐行寫入 log
    └ 行程結束 → 從紀錄移除
```

一律以絕對路徑啟動，不用 Tauri 的 sidecar，因為元件不一定來自安裝檔。元件由 App 直接啟動，不再開子行程，所以紀錄涵蓋全部行程。log 同時印到終端機與寫入檔案，預設在系統的 log 目錄，macOS 上是 `~/Library/Logs/me.aotoki.tsuzuri/`；設定頁可以改用別的目錄，重新啟動後生效。

### 3.2 清理

| 情境 | 機制 |
|---|---|
| App 正常結束 | 在 `RunEvent::Exit` kill 仍在執行的子行程 |
| App 當掉或被強制結束 | 下次啟動時清理 |
| PID 已被其他程式重用 | 名稱不符就不動它 |

下次啟動時 kill 紀錄中還活著且名稱相符的行程，Windows 用 `taskkill /T /F`。`tauri-plugin-shell` 只清理從 JS 端啟動的行程，所以 App 自己負責 Rust 端啟動的行程。當掉後的殘留會佔著 VRAM 直到下次啟動。

## 4 元件

相依：第 3 章，元件以行程執行。

行為：`components.md`、`licenses.md`。

### 4.1 尋找順序

```
  使用者指定的執行檔（例如 CUDA 版）
        │ 沒有，或檔案不在
        ▼
  偵測已安裝的版本（PATH、Homebrew、Nix；要能回應版本參數）
        │ 找不到
        ▼
  安裝檔內建的變體（依 0.4 自動選擇）
        │ 沒有
        ▼
  提示怎麼安裝
```

使用者指定的永遠優先，這是 CUDA 等進階設定的入口。macOS 的 App 讀不到 shell 的 PATH，所以常見的安裝目錄逐一列出。

### 4.2 內建變體

| 元件 | 變體 | 理由 |
|---|---|---|
| whisper.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 上游會刪舊 nightly |
| llama.cpp | CPU、OpenBLAS、Vulkan；macOS 用 Metal | 與 whisper.cpp 一致 |
| ffmpeg | 純音訊的 LGPL 版 | 只需要解出音軌，範圍小、授權單純 |

App 不在執行時下載元件。內建變體放在 `components/<元件>/<變體>/`，App 照 Build Manifest 列出的順序逐一嘗試，採用第一個能執行的變體；選擇結果顯示在設定頁，可以手動改。目前安裝檔只內建第一個變體，其他變體與 CUDA 版由使用者依 12.2 指定。

### 4.3 自行編譯

| 平台 | 編譯環境 |
|---|---|
| Windows | GitHub Actions 的 Windows runner，在 MSYS2 UCRT64 編譯，附上執行需要的 DLL |
| Linux | GitHub Actions 的 Linux runner，使用系統的 OpenBLAS、Vulkan 函式庫 |
| macOS | GitHub Actions 的 macOS runner，靜態連結 |

原始程式碼的版本、SHA256 與各平台的變體記在 `components.json`（Build Manifest），CI 與開發機跑同一支 `scripts/vendor.sh`。ffmpeg 的 `configure` 在 Windows 需要 MSYS2，所以 Windows 全部在那裡編譯。`vendor/` 與安裝檔同樣是 `<元件>/<變體>/` 的結構，開發時的 debug build 會先偵測它；打包時合併 `tauri.bundle.conf.json`，把 `vendor/` 放進安裝檔的 resources。

### 4.4 授權

| 元件 | 授權 | 我們的義務 |
|---|---|---|
| whisper.cpp、llama.cpp | MIT | 附上授權聲明 |
| ffmpeg | LGPL 2.1+ | 附原始碼、標示授權 |
| Rust 相依套件 | 見 `deny.toml` | cargo-deny 檢查、cargo-about 產生授權聲明 |
| Webview 打包套件 | 同 `about.toml` | 腳本檢查並產生聲明 |

ffmpeg 不開 GPL、nonfree，是獨立執行檔，Tsuzuri 不連結它的函式庫，使用者也能改用自己的。Webview 的聲明由 `scripts/webview-licenses.ts` 產生，含只在建置時用到、CSS 卻打包進去的 daisyUI 與 Tailwind。

## 6 工作流程

相依：第 1、3～5 章，流程串起的模組需要字幕資料、行程、元件與模型。

### 6.1 模組與流程

```
  媒體檔 ─▶ [轉錄模組] ─┐
                        ▼
  SRT 檔 ───────────▶ Transcript ─▶ [說話者辨識模組] ─▶ [翻譯模組]
                                     可選，需要媒體檔        │
                                                             ▼
                                                  Transcript（含譯文）
```

模組以 Transcript 為輸入或輸出，使用者可以組合它們。流程依序執行，前一個模組的行程全部結束後，下一個才開始。

### 6.2 任務

```
  字幕編輯（目前資源）
    ├─ [轉錄] ─▶ 轉錄模組 ─┬─▶ 段落逐段出現在編輯畫面
    │                        └─ 勾選完成後翻譯 ─┐
    └─ [翻譯] ─────────────────────────────────┴─▶ 翻譯模組 ─▶ 譯文逐批出現
```

| 任務 | 組成 | 可以開始的資源 |
|---|---|---|
| 轉錄 | 轉錄模組 | 有媒體檔 |
| 翻譯 | 翻譯模組 | 有主語言字幕 |
| 轉錄後翻譯 | 轉錄模組 → 翻譯模組 | 有媒體檔 |

編輯畫面是基本狀態，任務從它的 modal 開始，一次只跑一個。任務寫入的字幕在進行中不能改，結果算一步復原（2.5）。轉錄是翻譯的前置動作，勾選完成後翻譯時，轉錄的 modal 也列出翻譯的選項。目前組合寫死在程式裡，改成可組合後變成內建範本。

### 6.3 進度與取消

| 規則 | 說明 |
|---|---|
| 每個模組回報進度 | 名稱、百分比，能算就附「第 N / 共 M」 |
| Phase 序列 | 標出走過與目前的 |
| 算不出進度時 | 顯示不定進度，例如載入模型 |
| 顯示位置 | 編輯畫面上方 |
| 取消 | 結束行程，不寫檔 |

結果在同一畫面逐步出現，結束後進度消失，完成或失敗改以通知告知；取消時已顯示的留在畫面。Metal shader 第一次載入才編譯，冷啟動約 30 秒，偵測 llama-server 也會觸發。轉檔仍沒有百分比。

### 6.4 模型的狀態

```
            翻譯開始                          翻譯結束
  [空閒] ──────────▶ [載入翻譯模型] ──▶ [翻譯中] ──────▶ [保留 N 秒]
    ▲  ▲                                                   │    │
    │  └──────────────── 時間到，釋放 ──────────────────────┘    │
    │          轉錄結束                               轉錄開始，先釋放
    └──────────────────── [轉錄中] ◀───────────────────────────┘
  [空閒] ── 轉錄開始 ──────▶ [轉錄中]
```

| 規則 | 做法 |
|---|---|
| 一次一個任務 | 同一把鎖，後來的排隊 |
| 轉錄開始 | 先釋放翻譯模型；釋放不了就停止 llama-server |
| 保留期間再翻譯 | 取消排定的釋放，沿用已載入的模型 |

轉錄、翻譯與關掉常駐都先取得同一把鎖，不打斷進行中的任務。目前以這把鎖守住這些轉移，沒有明確的狀態列舉。流程改成可組合時，再把狀態與轉移寫成狀態機。

## 7 轉錄模組

相依：第 6 章，以模組身分加入流程。

行為：`transcribe.md`。

### 7.1 Step

```
  媒體檔 ─▶ ffmpeg ─▶ 16kHz 單聲道 WAV ─▶ whisper-cli ─▶ SRT ─▶ Transcript
```

先轉成統一格式，轉檔失敗與轉錄失敗可以分開診斷。兩個 Step 依序執行，whisper-cli 結束即釋放記憶體。

### 7.2 語言

| 設定 | 設計 |
|---|---|
| 轉錄語言 | 專案的主語言（2.3）；傳給 whisper-cli 的 `-l` |
| 語言清單 | 繁體中文、英文、日文，與翻譯共用 |
| 模型建議 | 依語言建議模型；Breeze-ASR-25 只適合中文 |

轉錄結果寫成主語言字幕，所以語言跟著專案，不在任務裡另選。每個代碼對各元件的意義只記在 Rust。模型建議尚未決定。

### 7.3 進度與串流

| 來源 | 內容 |
|---|---|
| stderr `main: processing` | 模型載入完成，開始轉錄 |
| stderr `progress = N%`（`-pp`） | 轉錄的百分比 |
| stdout `[開始 --> 結束]  文字` | 剛轉錄完成的段落 |
| 輸出 SRT | 結束時定稿，取代逐段累積的段落 |

whisper-cli 每處理完約 30 秒的音訊就送出一批段落與百分比，經過 pipe 也不會延到結束。段落逐批加進目前資源，最後一段之後保留一列 skeleton。完成時回報音檔長度與轉錄耗時以計算 RTF。

## 8 說話者辨識模組

相依：第 6、7 章，以模組身分加入流程，需要轉錄產出的 Transcript。

### 8.1 Step

```
  媒體檔、Transcript ─▶ [說話者辨識] ─▶ 標上說話者的 Transcript
```

| 規則 | 說明 |
|---|---|
| 輸入 | 媒體檔與轉錄產出 Transcript |
| 輸出 | 每個 Segment 標上說話者 |
| 開啟方式 | 專案設定或執行時的選項，預設關閉 |

whisper.cpp 不支援說話者辨識，所以在轉錄之後另外辨識。辨識與對應說話者的做法尚未決定。

### 8.2 工具選擇

| 條件 | 理由 |
|---|---|
| 在本機執行 | 設計承諾「本機處理」 |
| 結束即釋放記憶體 | 設計承諾「一次只載入一個模型」 |
| 授權允許隨 App 散布 | 同第 4.4 章的元件 |

候選工具尚待評估，這三項是選擇時的最低條件。

## 9 翻譯模組

相依：第 6 章，以模組身分加入流程。機制參考翻譯 PoC（qwen-translator-script），它針對小模型常見的漏翻、重複、跨句錯位設計了分層的修復。

行為：`translate.md`、`glossary.md`。

### 9.1 llama-server 生命週期

```
  App 啟動 ─▶ 背景啟動 router，不載入模型
  翻譯開始 ─▶ /models/load ─▶ 等到載入完成 ─▶ 送出各批翻譯
  翻譯結束 ─▶ 保留 N 秒 ─▶ /models/unload
  App 結束 ─▶ 停止 router 與它的模型行程
```

| 請求 | 做法 |
|---|---|
| 介面 | OpenAI 相容的 chat completions，以 async-openai 送出 |
| 內容 | 一批句子，各帶 index |
| 回應 | 以 JSON schema 限定格式，依 index 對回各句 |
| 思考模式 | 以 `chat-template-kwargs` 關閉，翻字幕用不到 |

| 常駐 | 做法 |
|---|---|
| 模型與參數 | Tsuzuri 寫的 preset |
| 一次一個 | `--models-max 1`、`--no-models-autoload`，只在翻譯開始時載入 |
| 保留 N 秒 | 由 Tsuzuri 計時後釋放，預設 0；改秒數不必重啟 router |
| 轉錄開始 | 先釋放翻譯模型 |
| 關掉常駐 | 每次翻譯才啟動 |
| router 意外結束 | 下一次翻譯重新啟動 |

請求附上前一批最後幾句的原文與譯文當參考。preset 記模型路徑、context 4096 與關閉思考，換模型時重讀；context 固定避免撐爆 VRAM。常駐省下啟動與關閉行程，router 不載入模型時不佔記憶體。

### 9.2 分批

| 規則 | 說明 |
|---|---|
| 每批數句 | PoC 預設 8 句，比逐句翻譯少很多請求 |
| 同一句不拆開 | 被切成多段的一句話排在同一批 |
| 失敗就拆半 | 重試仍失敗就拆兩半 |
| 說話者標籤 | 只送對話，譯完接回 |

```
  以重疊兩句的視窗請模型找出被切開的句子 ─▶ 同一句排進同一批 ─▶ 依序翻譯各批
```

說話者標籤由使用者開啟；冒號前是純數字的時間不算標籤，譯完行數變了就不接回。偵測在翻譯之前的 detect Phase 依序進行，失敗的視窗略過。串成超過兩倍批次大小的一組就不再保持完整，退回固定分批，避免請求撐爆 context。

### 9.3 詞彙表檔案

| 設定 | 設計 |
|---|---|
| 格式 | CSV，每欄一種語言 |
| 標頭 | 語言代碼 |
| `type` 欄 | 最後一欄，可省略 |
| 來源 | 專案的 `glossary.csv` |
| 編輯 | 詞彙表 modal |

每一列是同一個詞的各語言寫法，例如標頭 `zh-TW,en,ja`；以語言分欄，同一份就能譯成任何語言。`type` 欄的 `speaker` 表示說話者名稱，沒有這一欄視為沒有說話者。modal 列出所有支援的語言與說話者勾選，沒有檔案時由此建立，儲存時標頭寫成語言代碼與 `type`。它跟 `.spec/glossary.md` 無關。

### 9.4 詞彙表帶入

| 時機 | 做法 |
|---|---|
| 讀取 | 開專案與每次翻譯前 |
| 對應 | 主語言對目標語言 |
| 帶入 | 只帶該批出現的詞 |
| 檢查 | 不符就重試 |

小模型對陌生的專有名詞容易猜錯，其中一欄空白的列不用。`source,target` 標頭在專案記下翻譯語言時視為主語言與它，否則視為標頭錯誤。重試仍不符就保留最好的版本。說話者名稱也是詞，台詞叫到名字時譯法和標籤一致。

### 9.5 滾動摘要

| 設定 | 設計 |
|---|---|
| 內容 | 限字數的前文摘要 |
| 代價 | 每批多一次請求；PoC 實測總時間約多 30% |
| 限制 | 可能錯套人名 |

補足分批只看得到附近幾句的限制。每翻完一批更新一次，失敗就沿用上一版。沒搭配翻譯詞彙表時，模型會把摘要裡的人名錯套到其他人，所以只在有詞彙表時建議開啟。

### 9.6 自我修復

| 偵測到 | 處理 |
|---|---|
| 重複、漏翻、殘留原文、預留字 | 重試；仍失敗就保留原文 |
| 違反翻譯詞彙表、疑似吃掉否定詞 | 重試；仍失敗就保留目前最好的版本 |
| 自我檢查認為譯文屬於鄰句 | 重試；仍失敗就保留目前最好的版本 |
| 回應不是合法 JSON | 附上更正說明重試 |
| llama-server 無法回應 | 停止翻譯，不把原文當成譯文 |

```
  整批送出 ─▶ 有問題的句子帶前後文重試 ─▶ 仍失敗就拆半 ─▶ 剩一句仍失敗就退回
```

確定翻壞就不留下；問題輕微時，寧可保留不完美的譯文。殘留原文只在翻成英文時檢查；否定詞檢查只支援中翻英。

### 9.7 自我檢查

| 設定 | 設計 |
|---|---|
| 做法 | 先重述再指出對應句 |
| 範圍 | 只抓內容跑到鄰句 |
| 開啟方式 | 預設關閉，每批多出約一半的請求數 |

小模型批次翻譯時，常把一句的內容寫到隔壁句。每兩句一次請求，回應讀不懂就略過。先重述再比對，是 PoC 實測較穩定的判斷方式；判斷翻譯是否完整的做法誤判太多，已經放棄。

### 9.8 串流呈現

```
  第 1 批：標為翻譯中 ─▶ 翻譯 ─▶ 修復 ─▶ 檢查 ─▶ 寫進目前資源 ─▶ 畫面顯示
  第 2 批：……
  最後一批完成 ─▶ 寫出 [name].[lang].srt
```

| 時機 | 畫面與檔案 |
|---|---|
| 一批開始 | 它的譯文欄放 skeleton |
| 一批完成 | 顯示定稿 |
| 中途失敗 | 已顯示的留著，不寫檔 |
| 換了專案 | 後續批次不寫回 |

修復與檢查都在同一批之內完成，所以每批顯示的就是定稿，之後不會再改寫。失敗時不寫檔，避免留下只翻一半的檔案。

### 9.9 重新翻譯

| 設定 | 設計 |
|---|---|
| 對象 | 一段或勾選的段落 |
| 語言 | 顯示中的譯文 |
| 參考 | 前 3 句原文與譯文 |
| 後文 | 後 3 句原文，只供理解 |
| 修復 | 沿用 9.5，含詞彙表 |
| 略過 | 斷句偵測、滾動摘要 |
| 寫回 | 一步復原，不留備份 |

單句失去了一批的前後文，所以補上前後幾句。它修正的是已經留過備份的譯文，因此像編輯一樣寫回。

## 10 字幕校對與匯出

相依：第 1、2、6 章，校對的對象是目前資源的字幕。

行為：`editing.md`、`preview.md`；復原見第 2 章。

### 10.1 預覽與時間軸

```
  ┌ 預覽 ──────┬ 控制卡片 ──────────────────┐
  │ 影片，疊字  │ 播放、目前段落的時間與文字 │
  ├ 時間軸（全寬）─────────────────────────────┤
  │ 波形，段落區段交錯                        │◀─┐ 同一個目前段落
  └───────────────────────────────────────────┘  │
  ┌ 段落清單（全寬）──────────────────────────┐  │
  │ 目前段落：空白鍵只播這一段                │◀─┘
  └───────────────────────────────────────────┘
```

| 需要 | 做法 |
|---|---|
| 邊聽邊改 | 預覽與時間軸在清單上方 |
| 用上寬度 | 影片與卡片分寬，波形全寬 |
| 看譯文的樣子 | 疊字可換譯文或雙語 |
| 小螢幕 | 可收起預覽，只留清單 |
| 聽清楚一句 | 空白鍵只播目前段落 |
| 看出切段 | 波形上段落兩色交錯 |
| 長檔案 | Rust 以 ffmpeg 算波形 |
| 本機檔案 | 只開放專案目錄 |
| 播不了的格式 | 仍顯示波形 |

校對時要反覆聽同一句，所以單句播放不需要點按鈕。波形在 webview 解碼整段音訊會佔大量記憶體，交給 Rust 以內建的 ffmpeg 計算。拖動改時間見 10.2。

### 10.2 拖動改時間

| 需要 | 做法 |
|---|---|
| 不誤拖 | 只有目前段落可拖 |
| 改一邊 | 拖邊界 |
| 整段移動 | 拖本體，長度不變 |
| 不蓋到鄰段 | 夾在前後段落之間 |
| 對齊 | 8px 內吸附邊界與播放位置 |
| 暫時不吸附 | 拖曳時按住 Shift |
| 共用邊界 | 按住 Alt 一起移動 |
| 反悔 | Esc 還原 |
| 新增段落 | 空白處拖出，Enter 建立 |
| 用鍵盤 | F11、F12 設為播放位置 |
| 轉錄或翻譯中 | 不能拖 |

操作沿用 Aegisub 與 Subtitle Edit，放開才寫入，一次拖動是一步復原。譯文依時間對上原文，所以不允許重疊，按住 Shift 也不行。

### 10.3 編輯

| 可以改 | 做法 |
|---|---|
| 原文與譯文 | 直接在欄位改 |
| 說話者 | 選單或一次設定 |
| 時間戳 | 改時間、平移 |
| 段落 | 新增、刪除、合併、切割 |

whisper 的切段常需手動修正，調整時間戳與段落是校對重點。譯文依時間對上原文，所以這些改動一律寫回原文與每種譯文。說話者以原文為準，同步只改標籤，對不上的譯文不刪；選單列出用過與詞彙表的名稱。拖動改時間見 10.2。

### 10.4 對照

| 對照 | 做法 |
|---|---|
| 備份 | 原文與譯文各一份 |
| 其他譯文 | 可複選，唯讀 |
| 版面 | 一律上下疊 |

校對時要同時看原文改了什麼、譯文跟著改了什麼，也常參考其他語言的譯法。備份的差異標在各自的欄位，其他譯文疊在每段下方。上下疊在窄螢幕也放得下，分欄是之後的選項。

### 10.5 匯出

| 選項 | 內容 | 沒有譯文時 | 預設檔名 |
|---|---|---|---|
| 雙語 SRT | 依 1.3 的格式 | 停用 | `ep01.zh-TW.en.srt`；譯文在上時 `ep01.en.zh-TW.srt` |
| 另存原文 | 原文與說話者 | 可用 | `ep01.srt` |
| 另存譯文 | 目前譯文與說話者 | 停用 | `ep01.en.srt` |

原文與譯文已經自動寫回專案目錄（2.4），匯出只負責目錄裡沒有的雙語 SRT，以及存到其他地方。對話方塊預設開在專案目錄，檔名是資源名稱加上語言代碼。

### 10.6 編輯欄位

| 需要 | 做法 |
|---|---|
| 只收純文字 | `contenteditable="plaintext-only"`，字幕沒有格式 |
| 標記不寫進內容 | CSS Custom Highlight 以範圍著色，欄位值始終是字幕原文 |
| 游標在失焦後可見 | 自己畫 Cursor，隱藏原生游標 |
| 不支援 Highlight | 只顯示備份的文字，不標在欄位裡 |
| 與 Stimulus 搭配 | 由 controller 接上 |

textarea 不能在文字裡標記，後續的詞彙標記與選取都需要。ProseMirror、CodeMirror 為文件或程式碼設計，與逐段的字幕差太多，所以從原生元素做起。欄位本身是不綁定框架的模組。

### 10.7 Cursor

```
  CURRENT(i) --進入原文或譯文--> LIVE --離開--> KEPT
      ^                           ^              |
      |                           +--再次進入----+
      +------ 其他段成為目前段落、文字被換掉、欄位被鎖住
```

| 狀態 | 畫面 |
|---|---|
| 沒有 Cursor | 只有目前段落的底色 |
| LIVE | 閃爍的游標、選取底色 |
| KEPT | 靜止的游標、選取底色 |
| 選取一段文字 | 只標範圍，不畫游標 |

原生游標只在欄位有焦點時出現，選單與之後的浮動選單卻在焦點移走後才作用在 Cursor 上。所以一律自己畫，有沒有焦點看起來都一樣，不會兩套並存。

### 10.8 目前段落跟隨改動

| 情況 | 目前段落 | Cursor |
|---|---|---|
| 焦點進入列內 | 該段 | 只在原文或譯文 |
| 點其他段或時間軸 | 那一段 | 不保留 |
| 分割 | 後半段 | 後半段開頭 |
| 從選單或時間軸新增 | 新的段落 | 在它的原文 |
| 刪除目前段落 | 下一段，沒有就前一段 | 不保留 |
| 合併含目前段落 | 合併後的段落 | 不保留 |
| 改動其他段落 | 原本那一句 | 不變 |
| 外部改動，段數不變 | 保留 | 文字被換掉就不保留 |
| 外部改動，段數改變 | 無 | 無 |
| 換資源 | 無 | 無 |

盡量維持使用者所在的位置。外部改動指復原、重做、還原與轉錄，它們不說明增減了哪些段落，段數一變就清空。這些規則先依設想訂下，再看使用回饋調整。

## 11 介面

相依：第 2、6～10 章，畫面呈現專案、流程與各模組。

行為：`interface.md`。

### 11.1 視窗

| 情況 | 大小 |
|---|---|
| 首次開啟 | 佔螢幕可用範圍 80% |
| 取不到螢幕大小 | 1200×900 |
| 再次開啟 | 還原上次關閉時的大小與位置 |

編輯畫面要並排資源清單、影片預覽與段落清單，800×600 放不下；取不到螢幕大小時，把它放大 1.5 倍。

### 11.2 畫面分工

```
  ┌───────────────────────────────────────────────────────┐
  │ lecture ▾        [轉錄] [翻譯]  [匯出 ▾]  [設定]    │  工具列
  ├────────────┬──────────────────────────────────────────┤
  │ 資源清單   │ 字幕編輯：預覽、時間軸、段落清單         │
  └────────────┴──────────────────────────────────────────┘
       轉錄、翻譯、設定、詞彙表 ─▶ modal，關閉後回到編輯
```

| 畫面 | 內容 |
|---|---|
| 起始 | 開啟目錄或 SRT |
| 資源清單 | 資源與字幕狀態 |
| 字幕編輯 | 預覽、段落與進度 |
| 任務 modal | 選項與開始按鈕 |
| 詞彙表 modal | 以表格編輯 `glossary.csv` |
| 設定 modal | 專案與整體兩頁 |

編輯是唯一的主畫面，任務與設定都是暫時蓋在上面的 modal。起始畫面之後會列出最近的專案。設定的專案頁只影響這個目錄，整體頁放元件、模型與翻譯參數。各畫面的配置見 `docs/ui.md`。

### 11.3 多語系

| 規則 | 說明 |
|---|---|
| 預設語言 | 使用系統語言 |
| 沒有對應的翻譯 | 使用英文 |
| 手動切換 | 在設定改介面語言 |
| 文字來源 | 只由前端產生 |

後端以代碼與資料回報錯誤（Failure），只有前端產生介面文字。系統語言由作業系統回報，因為 WebView2 的 `navigator.language` 不會隨 Windows 的語言設定改變。

### 11.4 樣式

| 項目 | 設計 |
|---|---|
| 樣式工具 | TailwindCSS，隨前端一起由 Vite 建置 |
| 元件樣式 | daisyUI，以 Tailwind 外掛提供元件 class 與主題色 |
| 與 Stimulus 的分工 | Stimulus 管互動，Tailwind 的 class 寫在 HTML 上 |

畫面變多之後，手寫 CSS 難以維持一致。樣式跟著 HTML 走，controller 不需要知道樣式。元件與顏色取自 daisyUI，各畫面共用同一套外觀。

## 13 建置與釋出

相依：全部章節，打包的是前面各章的成果。

### 13.1 CI

```
  push、PR ─▶ spec（sumi）
           ├▶ licenses（cargo-deny、cargo-about）
           ├▶ frontend（Vitest、型別檢查）
           └▶ rust × 3 平台（fmt、clippy、test）
                   │ 全部通過，且是 push main 或手動觸發
                   ▼
              build × 3 平台
                   │ 每個元件的內建變體（build-component action）
                   │   cache 命中就還原，否則以 vendor.sh 編譯
                   │   確認能回應版本參數
                   ▼
              打包 ─▶ 上傳產物
```

action 釘 commit SHA，下載的工具釘 SHA256。Rust cache 以編譯器版本與 lockfile 為 key，存檔前移除會重新編譯的產物。元件 cache 以平台、變體、該元件的釘版與建置腳本為 key，只重編改到的元件；cache 過期時由 GitHub 清除，下次打包重新編譯。

### 13.2 產物與授權聲明

| 平台 | 產物 |
|---|---|
| Windows | `tsuzuri.exe`、NSIS 安裝檔、MSI |
| macOS | dmg、`.app` |
| Linux | 各種安裝包 |
| 全部 | `THIRD-PARTY-LICENSES.html`、`THIRD-PARTY-LICENSES-WEBVIEW.html` |

兩份授權聲明分別涵蓋 Rust 相依與 webview 打包的套件（4.4）。

### 13.3 釋出流程

```
  合併到 main ─▶ release-please 更新版本 PR
  合併版本 PR ─▶ 建立 tag 與 GitHub Release
              ─▶ CI 打包並附上產物、ffmpeg 原始程式碼、更新資訊
```

版號與 changelog 由 release-please 管理。不做作業系統的程式碼簽章；macOS 與 Windows 的放行步驟寫在 `README.md` 與 `README.zh-TW.md`。

### 13.4 自動更新

| 事項 | 設計 |
|---|---|
| 機制 | Tauri updater plugin |
| 更新來源 | GitHub Release 附帶的更新資訊檔 |
| 簽章 | Tauri 金鑰，必驗 |

私鑰放在 CI secret。updater 用自己的金鑰簽章，跟作業系統要求的程式碼簽章無關，所以不做程式碼簽章也能自動更新。

## 14 風險與待驗證

| 小節 | 範圍 |
|---|---|
| 14.1 平台 | 系統、驅動與打包 |
| 14.2 安全與行程 | 防護與行程紀錄 |
| 14.3 功能 | 字幕格式與模組 |

這些風險不阻擋目前的開發，但正式釋出前要逐一處理或接受。

### 14.1 平台

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| Windows 無自動測試 | 行程清理可能失效 | 實機已確認；補測試 |
| 變體實際速度 | 自動選擇順序要調 | 不同硬體量 RTF |
| Linux 系統函式庫 | 缺函式庫跑不起來 | `.deb` 宣告相依 |
| 沒有 Vulkan 驅動 | 內建元件無法執行 | 改指定 CPU 版 |
| macOS 簽章不完整 | 顯示「已損毀」 | 完整 ad-hoc 簽章 |

變體指 Vulkan 與 OpenBLAS；Linux 缺的是 libgomp1、libvulkan1。沒有驅動時先顯示無法執行，自動選擇上線後改為自動退回。macOS 產物只有 linker 的 ad-hoc 簽章，沒有「強制打開」，只能用 `xattr` 移除隔離；打包時以 `signingIdentity: "-"` 簽章後確認選項出現。

### 14.2 安全與行程

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| CSP 關閉 | 少一層防護 | 設 CSP 後確認介面 |
| 殘留行程只比名稱 | PID 重用時誤殺 | 評估比對啟動時間 |
| updater 私鑰遺失 | 無法再自動更新 | CI 以外另存備份 |

殘留行程以執行檔名稱比對，PID 被系統重用時可能誤殺同名行程。私鑰只存在 CI 時，一旦遺失，已安裝的版本就無法再自動更新。

### 14.3 功能

| 風險 | 影響 | 驗證方式 |
|---|---|---|
| 說話者取到第一個冒號 | 一般句子被當說話者 | 收集實際字幕 |
| 辨識工具未定 | VRAM 或授權不合 | 依 8.2 評估 |

Netflix 繁中指南的 `我問：「…」`、`日期：…`、`導演：…` 也會被當成說話者，寫出時冒號統一為 `: `。長度限制擋不住這些短句，故不採用。辨識工具可能超出 4GB VRAM，或授權不允許散布。
